# media: em28xx: double free of URB transfer buffers in `em28xx_alloc_urbs()`

|  |  |
|---|---|
| Bug class | Double free |
| Subsystem | drivers/media/usb/em28xx |
| Location | `drivers/media/usb/em28xx/em28xx-core.c`:1073-1090 (`em28xx_alloc_urbs()`) |

## Root cause

In `em28xx_alloc_urbs()` each streaming URB gets a `kzalloc()`'d transfer buffer, and the URB is
then flagged `URB_FREE_BUFFER`:

```c
urb->transfer_flags = URB_FREE_BUFFER;
...
usb_fill_bulk_urb(urb, udev, pipe, usb_bufs->buf[i], sb_size, em28xx_irq_callback, dev);
```

That flag transfers ownership of the buffer to the USB core — `usb_free_urb() -> urb_destroy()`
does `kfree(urb->transfer_buffer)`.

The driver keeps a *second* pointer to the same allocation in `usb_bufs->buf[i]`. The steady-state
teardown path is correct: `em28xx_uninit_usb_xfer()` only frees the **array** of pointers
(`kfree(usb_bufs->buf)`), never the elements — because the URBs own them.

The `kzalloc()` failure path inside the allocation loop is the one place that violates this. When
`usb_bufs->buf[i] = kzalloc(sb_size, GFP_KERNEL)` fails at some iteration `i > 0`, the unwinder
frees every buffer already installed in an URB, and then calls `em28xx_uninit_usb_xfer()`, which
calls `usb_free_urb()` on those very same URBs:

```c
/* drivers/media/usb/em28xx/em28xx-core.c : em28xx_alloc_urbs() */
	/* allocate urbs and transfer buffers */
	for (i = 0; i < usb_bufs->num_bufs; i++) {
		urb = usb_alloc_urb(usb_bufs->num_packets, GFP_KERNEL);
		if (!urb) {
			em28xx_uninit_usb_xfer(dev, mode);
			return -ENOMEM;
		}
		usb_bufs->urb[i] = urb;

		usb_bufs->buf[i] = kzalloc(sb_size, GFP_KERNEL);
		if (!usb_bufs->buf[i]) {
			for (i--; i >= 0; i--)
				kfree(usb_bufs->buf[i]);     /* first free of buf[0..i-1] */

			em28xx_uninit_usb_xfer(dev, mode);
			return -ENOMEM;
		}

		urb->transfer_flags = URB_FREE_BUFFER;   /* ownership -> USB core */

		if (xfer_bulk) { /* bulk */
			...
			usb_fill_bulk_urb(urb, udev, pipe, usb_bufs->buf[i],
					  sb_size, em28xx_irq_callback, dev);
		} else { /* isoc */
			...
			usb_fill_int_urb(urb, udev, pipe, usb_bufs->buf[i],
					 sb_size, em28xx_irq_callback, dev, 1);
			urb->transfer_flags |= URB_ISO_ASAP;
			...
		}
		urb->number_of_packets = usb_bufs->num_packets;
	}
	return 0;
```

```c
/* same file : em28xx_uninit_usb_xfer() — the second free */
	for (i = 0; i < usb_bufs->num_bufs; i++) {
		urb = usb_bufs->urb[i];
		if (urb) {
			if (!irqs_disabled())
				usb_kill_urb(urb);
			else
				usb_unlink_urb(urb);

			usb_free_urb(urb);       /* urb_destroy() -> kfree(urb->transfer_buffer) */
			usb_bufs->urb[i] = NULL;
		}
	}

	kfree(usb_bufs->urb);
	kfree(usb_bufs->buf);            /* only the pointer arrays — correct */
```

```c
/* drivers/usb/core/urb.c — the ownership contract */
static void urb_destroy(struct kref *kref)
{
	struct urb *urb = to_urb(kref);

	if (urb->transfer_flags & URB_FREE_BUFFER)
		kfree(urb->transfer_buffer);

	kfree(urb);
}
```

Each URB at index `j < i` has `URB_FREE_BUFFER` set and `urb->transfer_buffer == usb_bufs->buf[j]`,
so `urb_destroy()` frees the identical address a second time. The array slot is not cleared to
`NULL` after the `kfree()`, and clearing it would not help anyway — the URB holds its own copy of
the pointer. `i` buffers are double-freed on one pass.

The failing index `i` itself is safe (its URB was allocated but never filled and `usb_alloc_urb()`
zeroes `transfer_flags`), and slots `> i` are `NULL` from the `kcalloc()`. Only indices `< i` are
affected — which is every buffer allocated before the failure.

The code above is verbatim at mainline `2f1baf1fc8929e6c48370be543ad028ac7ad4131`
(`v7.2-rc7-93-g2f1baf1fc892`). It has the identical shape to the pre-image of commit
`9b3d5a6d952c` (an explicit `kfree()` of the transfer buffer sitting on the error path *after*
`URB_FREE_BUFFER` was set), and the identical shape to `03819abbeb11` ("net: usb: lan78xx: Fix
double free issue with interrupt buffer allocation"). Neighbouring `URB_FREE_BUFFER` users defend
against exactly this: `drivers/net/usb/usbnet.c:2258` does `urb->transfer_flags = 0;` before
`usb_free_urb()` with a comment naming the double free, and
`drivers/net/wireless/intersil/p54/p54usb.c:360` NULLs its local pointer right after setting the
flag. em28xx has neither guard.

The resulting primitive is a double `kfree()` of `i` freshly-freed slab objects of
attacker-influenced size (`sb_size` derives from the endpoint's `wMaxPacketSize` and the
alt-setting the driver picks, so the target cache is somewhat selectable). Classic SLUB
freelist-corruption primitive: an intervening allocation in the same cache can be reclaimed by the
second free, producing two live owners of one object -> use-after-free -> arbitrary read/write.
Arming it needs a controlled allocation failure at a chosen iteration and a heap groom in between
the two frees. The window between the `kfree()` loop and `usb_free_urb()` is short and runs in
process context with no sleep, which makes reliable interleaving hard, though `usb_kill_urb()`
inside `em28xx_uninit_usb_xfer()` can block and open the window.

## Trigger

1. Attach (or have attached) any em28xx-based USB analog/DVB capture device — the huge
   `em28xx_id_table` in `drivers/media/usb/em28xx/em28xx-cards.c` covers a large family of cheap
   USB TV/capture sticks. A local attacker with physical access can plug one in; on a system with
   such a device already present, no physical access is needed.
2. From userspace, start a capture stream — `VIDIOC_STREAMON` on `/dev/videoN`
   (`em28xx_start_analog_streaming()`), or open the DVB frontend / start a DVB feed
   (`em28xx_start_streaming()` in `em28xx-dvb.c`). Both funnel into `em28xx_init_usb_xfer()` ->
   `em28xx_alloc_urbs()`. On the DVB side the buffers are pre-allocated straight from device
   probe, before any frontend is attached, so a bare device attach reaches `em28xx_alloc_urbs()`
   with no `/dev` node and no ioctl.
3. Make one of the `kzalloc(sb_size, GFP_KERNEL)` calls in the loop fail at an iteration other than
   the first. `sb_size = packet_multiplier * max_pkt_size` and the loop runs `num_bufs` times
   (`EM28XX_NUM_BUFS` = 5, isoc `EM28XX_NUM_ISOC_PACKETS` = 64, so each buffer is tens of KB —
   these are order-3..order-5 allocations, i.e. genuinely failable under memory pressure).
   Deterministically: `CONFIG_FAILSLAB` / `CONFIG_FAIL_PAGE_ALLOC` via
   `/sys/kernel/debug/failslab/` with a suitable `probability`/`interval`, or simply drive the
   machine into sustained high-order allocation failure while looping `VIDIOC_STREAMON`.
4. The unwind runs and the same addresses are freed twice. With KASAN:
   `BUG: KASAN: double-free in usb_free_urb`. Without KASAN, the second free corrupts the SLUB
   freelist for the affected caches.

Because streaming can be started and stopped repeatedly from an unprivileged process holding the
video device node, the race between the attacker's memory pressure and the allocation loop can be
retried indefinitely until it lands.

**Privilege required**: none beyond access to the em28xx `/dev/video*` or DVB device node
(typically group `video`), plus the presence of the USB device. No `CAP_NET_ADMIN`/root needed.
If the attacker supplies the USB device (physical access / malicious hub), no existing device is
required — the DVB pre-allocation path is reached from probe, so no account, no capability and no
syscall on the victim is involved.

**CONFIG required**: `CONFIG_VIDEO_EM28XX`, plus `CONFIG_VIDEO_EM28XX_DVB` for the probe-time
route or `CONFIG_VIDEO_EM28XX_V4L2` for the `VIDIOC_STREAMON` route. Distro kernels ship
`em28xx`/`em28xx-dvb` as modules and autoload them on device attach.
