# ceph: slab out-of-bounds read in parse_reply_info_lease()

|  |  |
|---|---|
| Bug class | slab out-of-bounds read / type confusion on a truncated record |
| Subsystem | fs/ceph |
| Location | `fs/ceph/mds_client.c`:381–384 (and `*p = lend` at 397) (`parse_reply_info_lease()`) |

## Root cause

The bounds check covers a *different* extent than the read.

```c
lend = *p + struct_len;
ceph_decode_need(p, end, struct_len, bad);
*lease = *p;
*p += sizeof(**lease);
```

`struct_len` is read off the wire at line 374 (`ceph_decode_32_safe`) in the
`features == (u64)-1` path. It is validated against `end` — but it is **never required to be at
least `sizeof(struct ceph_mds_reply_lease)`**, which is 10 packed bytes
(`__le16 mask; __le32 duration_ms; __le32 seq;`, `include/linux/ceph/ceph_fs.h:598`). With
`struct_len = 0` the `ceph_decode_need()` is a no-op, and `*lease = *p` publishes a pointer to a
position with **zero** validated bytes behind it.

Two details let the malformed record slip through the rest of the parser rather than being
rejected:

1. `*p += sizeof(**lease);` overshoots — but the function then does `*p = lend;` (line 397),
   **rewinding the cursor** to `*p + struct_len`. So the overshoot never reaches a `_safe` macro
   that would fail closed.
2. Consequently `parse_reply_info_trace()`'s trailing `if (unlikely(*p != end)) goto bad;` still
   passes, and the truncated message parses "successfully".

Choosing `struct_v = 1` avoids the `struct_v >= 2` altname branch (which *does* carry a
`ceph_decode_32_safe` that would catch an overshot cursor), so nothing on the path validates the
10 bytes at all.

The caller then dereferences the published pointer unconditionally:
`le16_to_cpu(rinfo->dlease->mask)` and `le32_to_cpu(rinfo->dlease->duration_ms)` in
`ceph_fill_trace()` / `update_dentry_lease()` (`fs/ceph/inode.c:1442`, `:1772`), and
`di->lease_seq = le32_to_cpu(lease->seq)` in `__update_dentry_lease()` (`inode.c:1459`).

**The sibling function three declarations away proves this is an omission, not an invariant** —
`parse_reply_info_dir()` at `mds_client.c:343-346` does exactly the right thing:

```c
ceph_decode_need(p, end, sizeof(**dirfrag), bad);   /* sizeof-based check */
```

`parse_reply_info_lease()` never performs the equivalent. (The legacy `features != (u64)-1` path
is safe only by accident: it hard-codes `struct_len = sizeof(**lease)` at line 376.)

The full function, at HEAD `a500db7819c5`:

```c
/* fs/ceph/mds_client.c — parse_reply_info_lease() */

		u8 struct_compat;

		ceph_decode_8_safe(p, end, struct_compat, bad);

		/* struct_v is expected to be >= 1. we only understand
		 * encoding whose struct_compat == 1. */
		if (!struct_v || struct_compat != 1)
			goto bad;

		ceph_decode_32_safe(p, end, struct_len, bad);
	} else {

		*altname_len = 0;

	}

	lend = *p + struct_len;
	ceph_decode_need(p, end, struct_len, bad);   /* checks struct_len, NOT sizeof(**lease) */
	*lease = *p;                                 /* published with 0 validated bytes */
	*p += sizeof(**lease);                       /* overshoots ... */

	if (features == (u64)-1) {
		if (struct_v >= 2) {
			ceph_decode_32_safe(p, end, *altname_len, bad);   /* would catch it; use v1 */
			...
		}
	}
	*p = lend;                                   /* ... but the overshoot is rewound here */

```

At HEAD `a500db7819c5` there is no `if (struct_len < sizeof(**lease)) goto bad;` and no
`ceph_decode_need(p, end, sizeof(**lease), bad)` before `*lease = *p`.

The primitive is a read of up to 10 unvalidated bytes through a published pointer. The `end`
handed to this parser is the *inner* trace boundary, and in the common layout several length
fields follow the trace inside the same front buffer — so most of the 10 bytes are typically
still inside the allocation. The reliable consequence is therefore **type confusion on a
truncated record** (lease mask/duration/seq adopted from adjacent message bytes, corrupting
dentry lease state), with only the final 1–2 bytes leaving the slab object in the tail layout
described below. The read values reach userspace only indirectly, through dentry caching
behaviour.

## Trigger

1. Victim mounts CephFS from a cluster with a malicious or compromised MDS. No local privilege
   required.
2. Any userspace operation that produces a dentry reply — `open()`, `stat()`, `creat()`,
   `rename()`, or a `readdir()` (which reaches the same parser per entry at `mds_client.c:512`).
3. The MDS returns a `CEPH_MSG_CLIENT_REPLY` whose trace blob ends with a dentry lease record
   encoded as `struct_v = 1, struct_compat = 1, struct_len = 0`.
4. `handle_reply()` → `parse_reply_info()` (which narrows `end` to the trace blob at
   `mds_client.c:865`) → `parse_reply_info_trace()` → `parse_reply_info_lease()` (line 428).
5. `ceph_decode_need(p, end, 0)` passes; `rinfo->dlease` is set to the current cursor;
   `*p = lend` rewinds so the `*p != end` terminator passes and the reply is accepted.
6. `ceph_fill_trace()` → `update_dentry_lease()` reads `mask`, `duration_ms` and `seq` through
   that pointer — 10 bytes that were never validated.
7. To place the read outside the allocation the attacker positions the lease as the last element
   of the trace when `head->is_dentry && !head->is_target`: only the 4-byte extra-length and
   4-byte snapblob-length fields follow it in the front buffer, so with both set to zero just 8–9
   bytes remain and the tail of the 10-byte access runs past the end of the `kvmalloc()`'d front
   (`net/ceph/messenger.c:1984`). `mask` must be set so `le16_to_cpu(lease->mask) &
   CEPH_LEASE_VALID` holds at `inode.c:1442` for the deeper fields to be read.

Reaching the vulnerable versioned decode path requires `features == (u64)-1`, i.e.
`CEPHFS_FEATURE_REPLY_ENCODING` (bit 9) advertised in the MDS session-open reply.

`duration_ms` decodes as 0 in the truncated layout, so `have_lease` is obtained through
`have_dir_cap` instead: the parent-dir inode record in the same reply hands out
`CEPH_CAP_FILE_SHARED`.

Privilege required: **none on the client** (CephFS mounted; any unprivileged user's file
operation triggers a reply). The attacker must control an MDS the client talks to.

Required CONFIG: `CONFIG_CEPH_FS`, `CONFIG_CEPH_LIB`. `CONFIG_KASAN` is needed only to *observe*
the out-of-bounds read — the read itself happens on any config.
