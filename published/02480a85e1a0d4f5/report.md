# usb: gadget: f_ncm: use-after-free in `ncm_wrap_ntb()`

|  |  |
|---|---|
| Bug class | Use-after-free (read, then write) |
| Subsystem | drivers/usb/gadget/function |
| Location | `drivers/usb/gadget/function/f_ncm.c` (`ncm_wrap_ntb()`) |

## Root cause

`ncm->skb_tx_data` and `ncm->skb_tx_ndp` are fields of the long-lived
per-function `struct f_ncm`. When the NTH skb has been allocated (line 1059)
but the NDP skb allocation fails (line 1075), the code jumps to `err:`, which
frees both — but **never NULLs them**:

```c
/* drivers/usb/gadget/function/f_ncm.c — the allocation and the error path */
	if (!ncm->skb_tx_data) {
		...
		ncm->skb_tx_data = alloc_skb(...);
		if (!ncm->skb_tx_data)
			goto err;
		...
		ncm->skb_tx_ndp = alloc_skb(...);
		if (!ncm->skb_tx_ndp)
			goto err;
		...
	}
err:
	ncm->netdev->stats.tx_dropped++;

	if (skb)
		dev_kfree_skb_any(skb);
	if (ncm->skb_tx_data)
		dev_kfree_skb_any(ncm->skb_tx_data);	/* no ncm->skb_tx_data = NULL */
	if (ncm->skb_tx_ndp)
		dev_kfree_skb_any(ncm->skb_tx_ndp);	/* no ncm->skb_tx_ndp = NULL */
```

Every *other* release site in the file (lines 989 and 998) does clear the
field, which is what marks this as an omission rather than an invariant.

On the next transmit the function re-enters and evaluates:

```c
	if (ncm->skb_tx_data
	    && (ncm->ndp_dgram_count >= TX_MAX_NUM_DPE
	    || (ncm->skb_tx_data->len + div + rem + skb->len +
	    ncm->skb_tx_ndp->len + opts->ndp_size
	    + opts->dpe_size * 2) > max_size)) {
		...
```

`ncm->skb_tx_data` is non-NULL (freed), so the guard passes and `->len` is read
out of the freed `sk_buff` — a UAF read — while `ncm->skb_tx_ndp` is also
stale. If the branch is taken, `package_for_tx()` proceeds to
`put_ncm(&ntb_iter, ...)` writing through `ncm->skb_tx_data->data` — a
use-after-free **write** into a freed skb, with partially attacker-influenced
content (the NTB header fields derived from the packet being sent).

The freed object is the `struct sk_buff` allocated at `f_ncm.c:1059` and
released by the `err:` block without clearing `ncm->skb_tx_data`; the next
transmit re-reads it through the `if (ncm->skb_tx_data && ...)` guard.

## Trigger

1. A USB gadget configured with the NCM function (`g_ncm` / a configfs gadget
   with `ncm.0`), with a host attached and traffic flowing.
2. The `GFP_ATOMIC` `alloc_skb()` for the **NDP** skb at line 1075 fails while
   the NTH skb at line 1059 succeeded. This is an atomic-context allocation on
   the transmit path, so it fails naturally under memory pressure — which a
   local unprivileged process can generate.
3. `goto err` frees `ncm->skb_tx_data` and leaves the field pointing at it.
4. One more packet is sent over the NCM interface. `ncm_wrap_ntb()` re-enters,
   the `if (ncm->skb_tx_data && ...)` guard passes on the freed pointer, and the
   function reads `->len` and then writes through `->data`.

**Reachability and privilege.** Configuring the device as an NCM gadget
(configfs + UDC bind) requires root, but that is device configuration/state,
not a privilege the attacker must hold — in the same way a NIC driver bug
requires the NIC to be present. On a device that is already configured as an
NCM gadget (the normal deployed state of a phone/embedded device doing USB
tethering) there is no `capable()`/`ns_capable()` check anywhere on the path
`sendmsg()`/`sendto()` → `dev_queue_xmit()` → `eth_start_xmit()` (`u_ether.c`)
→ `dev->wrap()` = `ncm_wrap_ntb()`, so an unprivileged local process reaches the
buggy allocation with ordinary traffic. The primitive is a use-after-free write
into a freed `sk_buff` — a heavily groomable slab object — with header bytes
influenced by the transmitted packet.

**Configuration.** The vulnerable file is compiled only with
`CONFIG_USB_CONFIGFS_NCM=y` (which selects `CONFIG_USB_F_NCM` and
`CONFIG_USB_U_ETHER`). It is present as-is on any kernel that ships the NCM
gadget function, i.e. most Android and embedded gadget kernels.
