# net/ipv4/udp: slab out-of-bounds in inet_gso_segment() after SRv6 unsets the MAC header

|  |  |
|---|---|
| Bug class | slab out-of-bounds read |
| Subsystem | net/ipv4 (UDP receive / GSO segmentation) |
| Location | `net/ipv4/udp.c:2435-2454` (`udp_queue_rcv_skb()`) |

## Root cause

At mainline HEAD `238650ef6c7c7cca08e032527329424c9fbd70e5`
(`v7.3-rc3-82-g238650ef6c7c`), the unexpected-GSO receive path tries to restore
`skb->data` to the MAC header with `__skb_push(skb, -skb_mac_offset(skb))`. It
assumes the MAC offset is valid.

SRv6 End.DT4 VRF decapsulation explicitly calls `skb_unset_mac_header()` before
sending the inner IPv4 packet through VRF/IP receive. `decap_and_validate()`
calls `iptunnel_pull_offloads()`, which clears outer encapsulation GSO bits but
can leave inner `SKB_GSO_UDP_L4` or `SKB_GSO_FRAGLIST`. If the target UDP socket
does not accept that GRO type, `udp_unexpected_gso()` selects this branch.
`skb_mac_offset()` then warns and subtracts current data from `head + 0xffff`;
negating the large positive result and passing it to unsigned `__skb_push()`
moves `data` far outside the skb and corrupts its length before segmentation.
No MAC-header validity fallback exists.

```c
if (likely(!udp_unexpected_gso(sk, skb)))
        return udp_queue_rcv_one_skb(sk, skb);

BUILD_BUG_ON(sizeof(struct udp_skb_cb) > SKB_GSO_CB_OFFSET);
__skb_push(skb, -skb_mac_offset(skb));
segs = udp_rcv_segment(sk, skb, true);
```

The corrupted length is then consumed by `udp_rcv_segment()` and segmentation
reads outside the skb allocation. Observed as a KASAN slab-out-of-bounds read
in `inet_gso_segment()` reached from `__skb_gso_segment()` /
`udp_queue_rcv_skb()`, on an object in `kmalloc-4k` (read located 2047 bytes to
the right of the 4096-byte region). Expected impact is out-of-bounds access and
a kernel crash; the corruption magnitude is sentinel-derived and likely crashes
before yielding a controlled write, but it occurs in a remotely driven receive
path.

## Trigger

The path is exercised entirely with software-only networking:

1. Configure an SRv6 End.DT4 route terminating into a VRF and keep GRO enabled
   on the ingress path.
2. Bind an ordinary IPv4 UDP socket in the VRF without enabling acceptance of
   UDP GRO/fraglist packets.
3. Send an IPv4-in-IPv6/SRv6 UDP flow that GRO aggregates, leaving an inner UDP
   GSO type after outer decapsulation (a virtual ingress device supplying GSO
   metadata can exercise the same state).
4. End.DT4 pulls the outer headers, preserves the inner GSO type, and unsets
   `mac_header` before VRF delivery.
5. `udp_queue_rcv_skb()` sees an unexpected-GSO skb and evaluates the invalid
   MAC offset.
6. `__skb_push()` wraps the negative offset into a huge unsigned length,
   corrupting skb pointers before `udp_rcv_segment()`.

**Privilege:** no elevated privilege on the initial namespace is required. An
otherwise unprivileged user can reach the OOB path from an owned user +
network namespace, where `unshare(CLONE_NEWUSER|CLONE_NEWNET)` grants
`CAP_NET_ADMIN` over the owned network namespace (rtnetlink mutation is checked
by `netlink_net_capable(skb, CAP_NET_ADMIN)` and link-target checks use
`netlink_ns_capable(skb, net->user_ns, CAP_NET_ADMIN)`). On a system where an
administrator has already configured the affected SRv6 End.DT4/VRF/GRO
topology, it is network-reachable by a remote packet sender after setup.

**Config:** the code is built with `CONFIG_NET_VRF`,
`CONFIG_IPV6_SEG6_LWTUNNEL`, `CONFIG_TUN` and `CONFIG_USER_NS`. The
out-of-bounds access is surfaced by `CONFIG_KASAN`.
