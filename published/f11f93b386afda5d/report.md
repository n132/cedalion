# media: usbtv: slab out-of-bounds read in usbtv_iso_cb()

|  |  |
|---|---|
| Bug class | slab out-of-bounds read (kernel heap disclosed to userspace via the V4L2 frame buffer) |
| Subsystem | drivers/media/usb/usbtv |
| Location | `drivers/media/usb/usbtv/usbtv-video.c`:485-494 (`usbtv_iso_cb()`) |

## Root cause

The device-supplied per-packet `actual_length` is used as a loop bound at a
*finer granularity* than the amount each iteration actually consumes, so the last
iterations read past the end of the region the length describes — and, for the final
packet, past the end of the allocation.

The isochronous buffer is one `kcalloc` of `USBTV_ISOC_PACKETS` slots of `iso_size` bytes each:

```c
	int size = usbtv->iso_size;
	...
	ip->transfer_buffer = kcalloc(USBTV_ISOC_PACKETS, size, GFP_KERNEL);
	...
	ip->number_of_packets = USBTV_ISOC_PACKETS;
	ip->transfer_buffer_length = size * USBTV_ISOC_PACKETS;
	for (i = 0; i < USBTV_ISOC_PACKETS; i++) {
		ip->iso_frame_desc[i].offset = size * i;
		ip->iso_frame_desc[i].length = size;
	}
```

with `USBTV_ISOC_PACKETS = 8` and
`iso_size = usb_endpoint_maxp(ep) * usb_endpoint_maxp_mult(ep)` taken from
`intf->altsetting[1].endpoint[0]`.

The completion handler scans each packet in 256-byte steps:

```c
	for (i = 0; i < ip->number_of_packets; i++) {
		int size = ip->iso_frame_desc[i].actual_length;
		unsigned char *data = ip->transfer_buffer +
			ip->iso_frame_desc[i].offset;
		int offset;

		for (offset = 0; USBTV_CHUNK_SIZE * offset < size; offset++)
			usbtv_image_chunk(usbtv,
				(__be32 *)&data[USBTV_CHUNK_SIZE * offset]);
	}
```

`USBTV_CHUNK_SIZE` is **256**. But an *accepted* chunk consumes far more than 256 bytes:

```c
static void usbtv_chunk_to_vbuf(u32 *frame, __be32 *src, int chunk_no, int odd)
{
	int half;

	for (half = 0; half < 2; half++) {
		...
		memcpy(dst, src, USBTV_CHUNK/2 * sizeof(*src));
		src += USBTV_CHUNK/2;
	}
}
```

with `USBTV_CHUNK = 240`, i.e. two `memcpy`s of `120 * 4 = 480` bytes each — **960 bytes**, read from
`&chunk[1]`, plus the 4-byte header word. So each accepted chunk reads **964 bytes** starting at
`data + 256 * offset`, while the loop only guarantees `256 * offset < size`.

The 256-byte scan step is four times finer than the real 1024-byte on-wire chunk stride, and whether an
iteration is "accepted" is decided solely by a byte pattern the device wrote:

```c
	/* Ignore corrupted lines. */
	if (!USBTV_MAGIC_OK(chunk))
		return;
```
```c
#define USBTV_MAGIC_OK(chunk)	((be32_to_cpu(chunk[0]) & 0xff000000) == 0x88000000)
```

Concretely, with `iso_size = 3072`: the largest `offset` satisfying `256 * offset < 3072` is 11, giving
a chunk start at byte 2816 and a read extending to 2816 + 964 = **3780**, i.e. 708 bytes past the end of
that packet's slot. For packets 0..6 that spills into the next slot (still inside the `kcalloc`); for
packet **7**, the last one, it runs 708 bytes past the end of the allocation.

The 960 bytes read are `memcpy`'d directly into the vb2 plane:

```c
	buf = list_first_entry(&usbtv->bufs, struct usbtv_buf, list);
	frame = vb2_plane_vaddr(&buf->vb.vb2_buf, 0);
	/* Copy the chunk data. */
	usbtv_chunk_to_vbuf(frame, &chunk[1], chunk_no, odd);
```

so the out-of-bounds heap contents are delivered to whatever userspace process is dequeuing V4L2
buffers.

**Why this is not already fixed.** The destination side *is* bounded — `chunk_no >= usbtv->n_chunks`
returns early, so `dst` stays inside the frame. It is the **source** side that has no bound: nothing
checks `256 * offset + 964 <= size`, and nothing checks it against `iso_size` either. The USB core does
not help: `usb_submit_urb()` validates `iso_frame_desc[n].length <= maxp * mult` (satisfied — the driver
set it to exactly `iso_size`), and `actual_length <= length` always holds. The defect is entirely in the
driver's consumer loop.

On genuine usbtv hardware the device pads chunks to a 1024-byte stride, so `USBTV_MAGIC_OK()` is false
at the intermediate 256-byte positions and the bug lies dormant. A malicious or emulated device simply
places the 0x88 magic at the tail offsets, since it controls every byte of the isochronous payload.

## Trigger

Requires `CONFIG_VIDEO_USBTV` (it is `=m` in Debian/Ubuntu/Fedora stock kernels).
Privilege required: none beyond attaching the device and opening the V4L2 node.

1. Present a USB device matching usbtv's ID table (Fushicai USBTV007 video grabber).
2. Declare `altsetting[1].endpoint[0]` as an isochronous IN endpoint with a `wMaxPacketSize` /
   multiplier giving a convenient `iso_size` (e.g. masked 1024 with mult bits = 2, so
   `iso_size = 3072`).
3. From userspace, open `/dev/video*`, `VIDIOC_REQBUFS` / `VIDIOC_QBUF` / `VIDIOC_STREAMON` so that
   `usbtv` submits its isochronous URBs and a vb2 buffer is available on `usbtv->bufs`.
4. In each returned isochronous packet, set `actual_length` to the full `iso_size` and write a valid
   chunk header (`chunk[0] & 0xff000000 == 0x88000000`, a `chunk_no` below `usbtv->n_chunks`, and a
   `frame_id` matching the one established by the `chunk_no == 0` chunk) at byte offset **2816** of the
   packet — a position the loop still visits but from which 964 bytes do not fit.
5. `usbtv_chunk_to_vbuf()` reads 960 bytes starting at 2820. On the eighth packet those bytes come from
   past the end of the `kcalloc(8, 3072)` allocation and are copied into the V4L2 frame, which
   userspace then dequeues with `VIDIOC_DQBUF` and reads as image data.
