# net/ipv4/tcp_ao: use-after-free of a freed `tcp_ao_key` through the `tcp_ao_info` shared by `tcp_ao_time_wait()`

|  |  |
|---|---|
| Bug class | Slab use-after-free read in softirq (plus NULL pointer dereference on a second path) |
| Subsystem | net/ipv4, TCP-AO (`CONFIG_TCP_AO`) |
| Location | `net/ipv4/tcp_ao.c:316-335` (`tcp_ao_time_wait()`); read at `net/ipv4/tcp_ipv4.c:1052` (`tcp_v4_timewait_ack()`) |

## Root cause

`tcp_ao_time_wait()` hands a TIME_WAIT socket a refcounted reference to the full socket's
`struct tcp_ao_info` on the assumption that *"the full socket is on its way out, so handing the
TIME_WAIT socket a refcounted reference to the same `tcp_ao_info` is safe."* `struct tcp_ao_info`'s
own comment (`include/net/tcp_ao.h:132`) says the refcount "Protects twsk destruction" — it protects
the object's *lifetime*, not concurrent *mutation* of its contents.

That assumption is false on one path. `tcp_ao_time_wait()` does not copy anything:

```c
/* net/ipv4/tcp_ao.c — shares, does not clear tp->ao_info */
void tcp_ao_time_wait(struct tcp_timewait_sock *tcptw, struct tcp_sock *tp)
{
	struct tcp_ao_info *ao_info = rcu_dereference_protected(tp->ao_info, 1);

	if (ao_info) {
		...
		refcount_inc(&ao_info->refcnt);
		atomic_sub(omem, &(((struct sock *)tp)->sk_omem_alloc));
		rcu_assign_pointer(tcptw->ao_info, ao_info);
	}
	...
}
```

and it does **not** clear `tp->ao_info`. `tcp_time_wait()` then calls `tcp_done(sk)`, which sets
`TCP_CLOSE` and — crucially — only calls `inet_csk_destroy_sock()` when `SOCK_DEAD` is set:

```c
if (!sock_flag(sk, SOCK_DEAD))
	sk->sk_state_change(sk);
else
	inet_csk_destroy_sock(sk);
```

`tcp_fin()` reaches `tcp_time_wait(sk, TCP_TIME_WAIT, 0)` from `TCP_FIN_WAIT2` with **no** `SOCK_DEAD`
requirement — that is the ordinary `shutdown(fd, SHUT_WR)` case where the fd is still open:

```c
/* net/ipv4/tcp_input.c:4923-4926, tcp_fin() — the transition, with the fd still open */
	case TCP_FIN_WAIT2:
		tcp_send_ack(sk);
		tcp_time_wait(sk, TCP_TIME_WAIT, 0);
		break;
```

So after the peer's FIN, the process owns a live, fully usable `struct sock` in `TCP_CLOSE` whose
`tp->ao_info` is the *same object* a hashed TIME_WAIT socket is using from softirq. No lock is common
to the two: the setsockopt/connect writers hold the full socket's lock; the TIME_WAIT readers run in
softirq under RCU with the tw bucket lock only.

`tcp_disconnect()` never touches `tp->ao_info` (no `ao_info`/`md5sig` reference in the function), so
`connect(fd, {AF_UNSPEC})` returns `sock->state` to `SS_UNCONNECTED` and re-arms the socket for a
fresh `connect()` or `listen()` while the sharing persists.

Two concrete memory-safety consequences follow.

### (a) NULL dereference in softirq via `tcp_ao_connect_init()`

A second `connect()` on the surviving fd runs `tcp_ao_connect_init()` on the *shared* `ao_info`. It
prunes keys that do not match the new peer, and for each pruned key stores NULL into
`ao_info->current_key` / `ao_info->rnext_key` — with **plain stores**, not `WRITE_ONCE` — then
re-installs them a dozen lines later:

```c
/* net/ipv4/tcp_ao.c:1121-1142, tcp_ao_connect_init() — plain stores on the SHARED object */
	hlist_for_each_entry_safe(key, next, &ao_info->head, node) {
		if (!tcp_ao_key_cmp(key, l3index, addr, key->prefixlen, family, -1, -1))
			continue;
		if (key == ao_info->current_key)
			ao_info->current_key = NULL;      /* window opens */
		if (key == ao_info->rnext_key)
			ao_info->rnext_key = NULL;
		hlist_del_rcu(&key->node);
		atomic_sub(tcp_ao_sizeof_key(key), &sk->sk_omem_alloc);
		call_rcu(&key->rcu, tcp_ao_key_free_rcu);
	}
	key = tp->af_specific->ao_lookup(sk, sk, -1, -1);
	if (key) {
		if (!ao_info->current_key)
			ao_info->current_key = key;       /* window closes */
		...
```

Between those points the invariant documented at `include/net/tcp_ao.h:172` ("Established states are
fast-path and there always is current_key/rnext_key") is false. The TIME_WAIT socket trusts it with
no NULL check:

```c
/* net/ipv4/tcp_ipv4.c:1046-1053, tcp_v4_timewait_ack() */
if (key.ao_key) {
	struct tcp_ao_key *rnext_key;
	key.traffic_key = snd_other_key(key.ao_key);
	key.sne = READ_ONCE(ao_info->snd_sne);
	rnext_key = READ_ONCE(ao_info->rnext_key);
	key.rcv_next = rnext_key->rcvid;        /* no NULL check */
```

`tcp_ao_prepare_reset()`'s non-LISTEN branch (`net/ipv4/tcp_ao.c:801-802`) has the same unchecked
deref on the `TCP_TW_RST` path. Note `tcp_v4_rcv()`'s `do_time_wait:` path does **not** run
`tcp_inbound_hash()`, so an *unauthenticated* segment carrying a TCP-AO option is enough to drive
`tcp_v4_timewait_ack()` — the function's own comment says "FIXME: the segment to-be-acked is not
verified yet". The window widens linearly with the number of pruned keys, all of which the attacker
controls.

### (b) Use-after-free via the `del_async` path

After the FIN_WAIT2→TIME_WAIT transition, `connect(AF_UNSPEC)` then `listen()` puts the surviving
socket in `TCP_LISTEN` while `ao_info->current_key`/`rnext_key` still hold the keys chosen for the
finished connection. `TCP_AO_DEL_KEY` with `del_async=1` is accepted (`tcp_ao_del_cmd()` only requires
`sk_state == TCP_LISTEN`, `net/ipv4/tcp_ao.c:1871`) and `tcp_ao_delete_key()` (`net/ipv4/tcp_ao.c:1771-1810`)
`call_rcu()`s the key. The dangling `current_key`/`rnext_key` now belong to a *different socket* — the
TIME_WAIT socket, which legitimately maintains and dereferences them:

```c
/* net/ipv4/tcp_ipv4.c, tcp_v4_timewait_ack() — softirq reader, no NULL check, no common lock */
		rnext_key = READ_ONCE(ao_info->rnext_key);
		key.rcv_next = rnext_key->rcvid;
```

Commit `5ba9950bc907` does not close this: clearing `current_key`/`rnext_key` in the `del_async`
branch converts the UAF at `tcp_ipv4.c:1052` into the NULL deref of (a), because the object being
cleared is the TIME_WAIT socket's. The defect is the unsynchronised sharing, which nothing in this
tree guards.

### Consequence

(a) is a NULL-pointer dereference in softirq → oops/DoS; the NULL window is short but the trigger is
a packet, repeatable at line rate. (b) is a use-after-free read of a freed `tcp_ao_key`, whose
`->rcvid` byte is emitted into the wire ACK and whose `traffic_keys` are used to sign it — i.e. a
freed-object read whose result is partly observable to the peer, on an object whose size is chosen by
the attacker (`TCP_AO_ADD_KEY` key length) and therefore groomable. For a 12-byte MAC the freed
object is a `struct tcp_ao_key` plus its `traffic_keys[]` in `kmalloc-256`, and the byte read is
`rcvid` at offset 129 into that region. The free is attacker-timed and the window is a full RCU grace
period plus however long the TIME_WAIT socket lives (up to `TCP_TIMEWAIT_LEN`, 60s).

Secondary, non-memory-safety effects of the same sharing: `TCP_AO_INFO`/`TCP_AO_DEL_KEY` with
`set_current`/`set_rnext` on the surviving socket silently re-point the TIME_WAIT socket's signing
keys; `tcp_ao_connect_init()`/`tcp_ao_finish_connect()` overwrite the shared `lisn`/`risn`/`snd_sne`/
`rcv_sne` and recompute every key's cached traffic keys in place; and `twsk_rcv_nxt_update()`
(`net/ipv4/tcp_minisocks.c:57-68`) bumps the shared `ao->rcv_sne` from the *old* peer's packets,
desynchronising the receive SNE of whatever new authenticated connection the reused socket has
established (remotely triggerable disruption of an unrelated connection).

The v6 twin of the reader is at `net/ipv6/tcp_ipv6.c:~1161`.

## Trigger

Unprivileged — no capability of any kind is required, and none of the TCP-AO setsockopt handlers
(`tcp_ao_add_cmd()`, `tcp_ao_del_cmd()`, the `TCP_AO_*` cases of `do_tcp_setsockopt()`) contain any
`capable()` / `ns_capable()` check. Requires `CONFIG_TCP_AO=y` plus a crypto algorithm usable by
TCP-AO (`cmac(aes)`), and a cooperating peer — loopback is fine. Observed on `7.0.0+` at commit
`3cd8b194bf3428dfa53120fee47e827a7c495815`.

1. `fd = socket(AF_INET, SOCK_STREAM, 0)`.
2. `setsockopt(fd, TCP_AO_ADD_KEY, ...)` twice — key `K1` matching peer **P1**, key `K2` matching
   peer **P2**. Add extras matching P1 to widen the window in (a).
3. `connect(fd, P1)` → `tcp_ao_connect_init()` sets `current_key = rnext_key = K1`; ESTABLISHED.
4. `shutdown(fd, SHUT_WR)` → `FIN_WAIT1` → peer ACKs → `FIN_WAIT2`.
5. Peer sends FIN → `tcp_fin()` → `tcp_time_wait(sk, TCP_TIME_WAIT, 0)`. Now:
   `ao_info->refcnt == 2`, a hashed TIME_WAIT socket uses it, `sk_state == TCP_CLOSE`, **fd still
   open**, `tp->ao_info` unchanged.
6. `connect(fd, {.sa_family = AF_UNSPEC})` → `tcp_disconnect()`; `sock->state = SS_UNCONNECTED`.
   `ao_info` untouched.
7a. **(a)** `connect(fd, P2)` → `tcp_ao_connect_init()` prunes the P1 keys, transiently NULLing
   `current_key`/`rnext_key`. Concurrently, from P1, send an AO-carrying out-of-window ACK (or let the
   peer retransmit its FIN) to the TIME_WAIT 4-tuple → `tcp_v4_timewait_ack()` →
   `rnext_key->rcvid` on NULL → oops in softirq.
7b. **(b)** `listen(fd, 1)`; `getsockopt(fd, TCP_AO_INFO)` to read the current key id;
   `setsockopt(fd, TCP_AO_DEL_KEY, {.del_async = 1, <that id>})`; then let the peer retransmit to the
   TIME_WAIT 4-tuple → `tcp_v4_timewait_ack()` dereferences the RCU-freed `tcp_ao_key`.

The attacker controls both keys and their lengths (and therefore the freed object's slab size), the
moment of the `call_rcu()` free, and the `rnext_keyid` carried in the triggering segment. That
segment must name a key that is *still* on the list for `tcp_ao_established_key()` to succeed and
reach `tcp_ipv4.c:1052`, while `ao_info->rnext_key` still points at the freed one. Because
`do_time_wait:` never calls `tcp_inbound_hash()`, the segment is not authenticated. The final trigger
is a single TCP segment to the TIME_WAIT 4-tuple, which the remote peer of a finished TCP-AO
connection produces by simply retransmitting.
