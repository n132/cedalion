# mac80211: use-after-free in `ieee80211_key_replace()` `-ENOLINK` path

|  |  |
|---|---|
| Bug class | Use-after-free (linked-list corruption) |
| Subsystem | `net/mac80211` |
| Location | `net/mac80211/key.c:474-486` (`ieee80211_key_replace()`) |

## Root cause

`ieee80211_key_replace()` is the single chokepoint that performs all three pieces of unlink
bookkeeping, and it performs them at the **end** of the function:

* clears the cached selectors `sdata->default_unicast_key`, `link->default_multicast_key`,
  `link->default_mgmt_key`, `link->default_beacon_key` (via `__ieee80211_set_default_*key(link, -1)`);
* clears the slot — `rcu_assign_pointer(link_sta->gtk[idx], new)`, `sta->ptk[idx]`, `sdata->keys[idx]`
  or `link->gtk[idx]`;
* `if (old) list_del_rcu(&old->list);`

It also has two early `return -ENOLINK` exits, **before all of the above**:

```c
/* net/mac80211/key.c — the two early exits, BEFORE any bookkeeping */
	if (link_id >= 0) {
		if (!link) {
			link = sdata_dereference(sdata->link[link_id], sdata);
			if (!link)
				return -ENOLINK;
		}

		if (sta) {
			link_sta = rcu_dereference_protected(sta->link[link_id],
							     lockdep_is_held(&sta->local->hw.wiphy->mtx));
			if (!link_sta)
				return -ENOLINK;
		}
	}

	...
	/* ~100 lines later, the bookkeeping that was skipped: */
	if (new)
		list_add_tail_rcu(&new->list, &sdata->key_list);

	if (sta) {
		if (pairwise) {
			rcu_assign_pointer(sta->ptk[idx], new);
			...
		} else {
			rcu_assign_pointer(link_sta->gtk[idx], new);
		}
	} else {
		... __ieee80211_set_default_key(link, -1, true, false); ...
	}

	if (old)
		list_del_rcu(&old->list);          /* <-- never reached on -ENOLINK */

	return 0;
}
```

All three teardown callers — `ieee80211_free_keys_iface()` (`key.c:1079-1099`),
`ieee80211_remove_link_keys()` (`key.c:1101-1118`) and `ieee80211_free_sta_keys()`
(`key.c:1178-1207`) — **ignore the return value** and free the key regardless:

```c
/* net/mac80211/key.c — caller discards the error and frees anyway */
static void ieee80211_free_keys_iface(struct ieee80211_sub_if_data *sdata,
				      struct list_head *keys)
{
	list_for_each_entry_safe(key, tmp, &sdata->key_list, list) {
		ieee80211_key_replace(key->sdata, NULL, key->sta,
				      key->conf.flags & IEEE80211_KEY_FLAG_PAIRWISE,
				      key, NULL);
		list_add_tail(&key->list, keys);
	}
	...
}

/* ieee80211_free_sta_keys() */
		ieee80211_key_replace(key->sdata, NULL, key->sta, ..., key, NULL);
		__ieee80211_key_destroy(key, ...);     /* frees it outright */
```

When the `-ENOLINK` exit is taken, `list_del_rcu(&old->list)` never runs, so `key->list` is still
linked into `sdata->key_list`. `list_add_tail(&key->list, keys)` then overwrites `key->list.next/prev`
to point into the caller's on-stack `keys` head, while `sdata->key_list`'s neighbours still point at
`&key->list`. `ieee80211_free_key_list()` → `__ieee80211_key_destroy()` frees the key, and
`sdata->key_list` is left containing a freed node whose `prev` points at a dead stack frame.

Anything that subsequently walks or writes `sdata->key_list` touches freed memory:
`ieee80211_key_link()`'s `list_add_tail_rcu(&new->list, &sdata->key_list)` (a UAF **write** through
the freed node's `prev->next`), `ieee80211_iter_keys()` / `_ieee80211_iter_keys_rcu()`, and the
debugfs key dumps. Additionally, if the `sta` was destroyed before the key, `ieee80211_key_replace()`
itself dereferences the freed `sta->link[link_id]`.

**Why it is not already fixed there:** the callers have no error handling at all — the return value is
discarded in every one of the three sites — and `ieee80211_del_key()` cannot be used by userspace to
clean the orphan up, because `ieee80211_lookup_key()` finds link-station group keys through
`link_sta->gtk[]`, which is exactly the array that has already gone away. Note also that
`ieee80211_free_sta_keys()` only walks `sta->deflink.gtk[]` and `sta->ptk[]`, so a key installed into
a *non-default* link-station's `gtk[]` is not freed at station teardown either — it survives with
`key->sta` dangling.

The resulting primitive is a UAF write on the re-add path (`list_add_tail_rcu` stores through a freed
node's `prev`), which is a strong arbitrary-ish write primitive if the freed `struct ieee80211_key`
slot is groomed; UAF read on the iterate/debugfs paths. `struct ieee80211_key` is variable-sized
(`kzalloc(sizeof(*key) + key_len)`), so the attacker chooses the slab cache. The whole flow is
serialised under the wiphy mutex, so grooming has to happen between the free and the re-add rather
than concurrently.

## Trigger

Reachable from userspace through nl80211 (generic netlink). The code path exists on any kernel that
ships `CONFIG_CFG80211` and `CONFIG_MAC80211` (i.e. every distro kernel); reaching it additionally
needs an MLO-capable 802.11 driver. `mac80211_hwsim`
(`drivers/net/wireless/virtual/mac80211_hwsim.c`, `CONFIG_MAC80211_HWSIM`) is a pure software radio
that advertises `WIPHY_FLAG_SUPPORTS_MLO` when created with `HWSIM_ATTR_MLO_SUPPORT`, so no PCI/USB
wireless hardware is required; on a host with an MLO-capable wireless driver the same nl80211 command
sequence reaches the identical code path.

**Privilege required.** `CAP_NET_ADMIN` over the wiphy's network namespace, which an unprivileged
local user can obtain over a namespace of their own: every command on the path —
`HWSIM_CMD_NEW_RADIO` and `NL80211_CMD_{SET_INTERFACE,ADD_LINK,START_AP,NEW_STATION,ADD_LINK_STA,`
`NEW_KEY,REMOVE_LINK_STA,REMOVE_LINK}` — carries `.flags = GENL_UNS_ADMIN_PERM`
(`net/wireless/nl80211.c:19178`, `:19918-19949`; `mac80211_hwsim.c:6895`), i.e.
`netlink_ns_capable(skb, net->user_ns, CAP_NET_ADMIN)` rather than `capable()` against
`init_user_ns`. The hwsim family is `.netnsok = true`, and `mac80211_hwsim_new_radio()` does
`net = genl_info_net(info); wiphy_net_set(hw->wiphy, net);` (`mac80211_hwsim.c:5616-5619`), so the
radio is created inside the caller's netns. A uid with no capabilities that does
`unshare(CLONE_NEWUSER|CLONE_NEWNET)` therefore reaches the whole sequence.

Two further prerequisites hold on this driver: `cfg80211_validate_key_settings()` rejects a group key
carrying a MAC address unless `WIPHY_FLAG_IBSS_RSN`, which hwsim sets unconditionally
(`mac80211_hwsim.c:5821`); and `sta_link_apply_parameters()` needs `ieee80211_get_link_sband(link)`,
which needs a `chanctx_conf` on the link, so each link must have the AP actually started. hwsim never
sets `IEEE80211_HW_SUPPORTS_PER_STA_GTK`, so a per-STA GTK falls to `out_unsupported`; hwsim also does
not set `SW_CRYPTO_CONTROL`, so for `WLAN_CIPHER_SUITE_CCMP` that path `return 0`s and the key is
installed in software, after which `ieee80211_key_replace()` proceeds normally and stores it in
`link_sta->gtk[idx]`.

The sequence, once an AP-mode MLD interface with two started links and an MLD station carrying a link
station for link 1 exists:

1. `NL80211_CMD_NEW_KEY` with a group cipher, `NL80211_ATTR_MAC` = the station's
   MLD address and `NL80211_ATTR_MLO_LINK_ID = 1` stores the key in
   `sta->link[1]->gtk[1]` with `key->conf.link_id = 1`, `key->sta = sta`, and
   links it into `sdata->key_list`.
2. `NL80211_CMD_REMOVE_LINK_STA` for link 1 → `sta_remove_link()`
   (`net/mac80211/sta_info.c:414`) NULLs `sta->link[1]` and frees the `link_sta`
   without touching its `gtk[]`. The key is now orphaned but still on
   `sdata->key_list`.
3. `NL80211_CMD_REMOVE_LINK` for link 1 → `cfg80211_remove_link()` →
   `cfg80211_stop_ap()` → `ieee80211_stop_ap()` (`net/mac80211/cfg.c:1914`) →
   **first** `ieee80211_remove_link_keys(link1, &keys)`. For that key,
   `ieee80211_key_replace()` takes the `if (sta) { ... if (!link_sta) return
   -ENOLINK; }` exit at `key.c:481-486`, so `list_del_rcu(&old->list)` at
   `key.c:586` never runs. The caller discards the return value, does
   `list_add_tail(&key->list, keys)` on a node that is *still* linked into
   `sdata->key_list`, and `ieee80211_free_key_list()` frees the key.
   `sdata->key_list.next/prev` now point into freed memory.
4. `cfg80211_remove_link()` continues into `rdev_del_intf_link()` →
   `ieee80211_vif_update_links()` → `ieee80211_tear_down_links()` → the
   **second** `ieee80211_remove_link_keys()`. Its
   `list_for_each_entry_safe(key, tmp, &sdata->key_list, list)` reads the freed
   node → KASAN slab-use-after-free (read of 8 bytes at object+24, i.e.
   `key->list`), then GPF/panic.

The whole free-and-reuse happens inside the single `NL80211_CMD_REMOVE_LINK` call, because
`cfg80211_remove_link()` calls `ieee80211_remove_link_keys()` twice. Alternatively, tearing the
interface down (`ip link set <iface> down` → `ieee80211_free_keys_iface()`) reaches the same
`-ENOLINK` leak, and re-adding any key on the same `sdata` afterwards (`NL80211_CMD_NEW_KEY` →
`list_add_tail_rcu(&new->list, &sdata->key_list)`) turns it into the UAF write. The bug is a pure
ordering/bookkeeping defect, not a race: the sequence is single-threaded and deterministic.
