# net/psp: use-after-free of the listener's `psp_assoc` inherited by `sk_clone_lock()`

|  |  |
|---|---|
| Bug class | Use-after-free (reference not taken on clone) |
| Subsystem | `net/psp`, `net/core` |
| Location | `net/core/sock.c` (`sk_clone_lock()`); field at `include/net/sock.h:468`; consumer at `net/ipv4/af_inet.c:167` |
| Fixed upstream by | `1d2929d0850f` ("net: psp: do not inherit the Rx association on clone") |

## Root cause

The child inherits a *resource* (a refcounted object) that the clone path never
accounts for, so ownership is duplicated without the refcount that would make
duplication safe.

`sk->psp_assoc` (`include/net/sock.h:468`) is a refcounted `struct psp_assoc`
holding the socket's PSP (PSP Security Protocol) association. It sits past
`sk_dontcopy_end`, so `sock_copy()` bulk-copies it into every cloned socket.
`net/core/sock.c` contains **no PSP handling at all** — so the accepted child
ends up with a second pointer to the listener's association and **no
`refcount_inc()`**.

```c
/* include/net/sock.h:468 — bulk-copied by sock_copy(), never reset or ref'd in sk_clone_lock() */
	struct psp_assoc __rcu	*psp_assoc;
```

The kernel demonstrates the correct discipline for the *other* place a
`psp_assoc` pointer is duplicated — the timewait socket:

```c
/* net/psp/psp_sock.c:266-273 */
void psp_twsk_init(struct inet_timewait_sock *tw, const struct sock *sk)
{
	struct psp_assoc *pas = psp_sk_assoc(sk);

	if (pas)
		refcount_inc(&pas->refcnt);	/* <-- the reference sk_clone_lock() is missing */
	rcu_assign_pointer(tw->psp_assoc, pas);
	tw->tw_validate_xmit_skb = psp_validate_xmit;
}
```

The child, however, gets the pointer for free — and its destructor drops a
reference it never took:

```c
/* net/ipv4/af_inet.c:167 — inet_sock_destruct() */
	psp_sk_assoc_free(sk);		/* -> psp_assoc_put() */
```

So with a listener holding the sole reference (refcnt == 1):

1. `accept()` clones → child shares the pointer, refcnt still 1.
2. `close(child_fd)` → `inet_sock_destruct()` → `psp_sk_assoc_free()` →
   `psp_assoc_put()` → refcnt 0 → the association is freed (via
   `call_rcu(psp_assoc_free_queue)`).
3. The listener's `sk->psp_assoc` still points at the freed object → UAF on the
   next PSP operation, and a second `psp_assoc_put()` at the listener's own
   close.

PSP's clone-path integration covered `inet_timewait_sock` only
(`psp_twsk_init`). `sk_clone_lock()` was never taught about the field, and
because `psp_assoc` lives in the bulk-copied region there is no compile-time or
runtime signal that it was missed.

The resulting primitive is a premature free of a `struct psp_assoc` that remains
reachable from a live listening socket — a classic refcount-underflow UAF, with
a controllable reallocation window between the child's close and the listener's
next use. A second `psp_assoc_put()` follows at listener close.

The first use after the free is a read: `tcp_v4_do_rcv()`
(`net/ipv4/tcp_ipv4.c:1832`) → `psp_sk_rx_policy_check()` →
`__psp_sk_rx_policy_check()` reads `pas->tx.spi`
(`include/net/psp/functions.h:107`). It runs for `TCP_LISTEN` sockets too, so a
plain SYN at the listener touches the freed object.

A secondary consequence beyond the refcount bug: accepted children silently
inherit the listener's PSP RX policy and its
`sk_validate_xmit_skb = psp_validate_xmit` hook, which is a policy-inheritance
question of its own.

## Trigger

Requires `CONFIG_INET_PSP` and a PSP-capable device
(`drivers/net/netdevsim/psp.c` provides one for testing, so no physical NIC is
needed).

1. Create a PSP device / netdevsim instance in a netns.
2. `socket(AF_INET, SOCK_STREAM, 0)`; `bind()`; `listen()`.
3. Attach a PSP RX association to the **listening** socket via the PSP
   generic-netlink interface (`PSP_CMD_RX_ASSOC`). Notably this op carries **no
   `GENL_ADMIN_PERM`** in `net/psp/psp-nl-gen.c`,
   `psp_assoc_device_get_locked()` checks only `sk_is_tcp()` with no
   socket-state check, and `psp_dev_check_access()` only requires the device to
   be in the caller's netns — so a listener can be given an association.
4. Drive one inbound TCP connection; `accept()` it. The child now shares the
   association with no added reference.
5. `close()` the accepted fd. `inet_sock_destruct()` drops the refcount to zero
   and the association is freed.
6. Touch the listener's association again — any PSP-relevant operation, or
   simply `close()` the listener — for a use-after-free / double put.

Conditions that have to hold:

- The accepted child must not go to `TIME_WAIT`, whose `psp_twsk_init()` *would*
  have taken the missing reference and masked the free for ~60s.
- A version-0 Rx-only association leaves `pas->tx.spi == 0`, so
  `__psp_sk_rx_policy_check()` returns 0 for plain non-PSP inbound connections
  and the `accept()` actually happens.
- `PSP_A_ASSOC_DEV_ID` must be passed explicitly: `psp_dev_get_for_sock()` needs
  `__sk_dst_get(sk)`, and a listening socket has no dst, so the device is
  resolved from the attribute instead.

Privilege required: none beyond the ability to create the netns/device and issue
the PSP netlink op (which lacks `GENL_ADMIN_PERM`). There is no `capable()` /
`ns_capable()` check anywhere on the chain from `listen()` to the buggy line.

Configuration exposure: `CONFIG_INET_PSP=y` is **required** — it is the option
that introduces the buggy field and its refcounting. The upstream default is `n`
today, but the option exists precisely to be turned on for PSP-capable NICs; any
kernel that ships PSP support is affected. `CONFIG_NETDEVSIM=y` is **not**
required on a machine that actually has a PSP-capable NIC; it only substitutes
for that hardware.
