# ALSA: usb-audio: slab out-of-bounds write in prepare_playback_urb()

|  |  |
|---|---|
| Bug class | Slab out-of-bounds write past a `struct urb` allocation |
| Subsystem | sound/usb |
| Location | `sound/usb/pcm.c:1553` (`prepare_playback_urb()`), via `sound/usb/endpoint.c:494` (`snd_usb_queue_pending_output_urbs()`) |

## Root cause

An implicit-feedback playback endpoint adopts the capture endpoint's packet count into a
URB that was allocated for fewer packets, overflowing `urb->iso_frame_desc[]`.

Each playback URB is allocated for exactly `u->packets` isochronous frames:

```c
/* sound/usb/endpoint.c:1243-1252 — the URB is allocated for exactly u->packets frames */
	for (i = 0; i < ep->nurbs; i++) {
		struct snd_urb_ctx *u = &ep->urb[i];
		u->index = i;
		u->ep = ep;
		u->packets = urb_packs;

		if (fmt->fmt_type == UAC_FORMAT_TYPE_II)
			u->packets++; /* for transfer delimiter */
		u->buffer_size = maxsize * u->packets;
		u->urb = usb_alloc_urb(u->packets, GFP_KERNEL);
```

`usb_alloc_urb(n)` is `kmalloc_flex(*urb, iso_frame_desc, n)` (`drivers/usb/core/urb.c`), so the
`iso_frame_desc[]` flexible array has exactly `u->packets` slots and the object is sized accordingly.
`u->packets` is stored in `ctx->packets`.

```c
/* drivers/usb/core/urb.c — iso_frame_desc[] is sized by that argument */
struct urb *usb_alloc_urb(int iso_packets, gfp_t mem_flags)
{
	struct urb *urb;

	urb = kmalloc_flex(*urb, iso_frame_desc, iso_packets, mem_flags);
```

For an **implicit-feedback** playback endpoint, the capture (sync-source) endpoint's completion handler
overwrites that field. `snd_usb_handle_sync_urb()` copies the IN endpoint's packet count into the queued
packet info:

```c
/* sound/usb/endpoint.c:1822-1831 — the sync source publishes ITS packet count */
	out_packet->packets = in_ctx->packets;
	for (i = 0; i < in_ctx->packets; i++) {
		if (urb->iso_frame_desc[i].status == 0) {
			unsigned int frames =
				urb->iso_frame_desc[i].actual_length / sender->stride;
			out_packet->packet_size[i] = min(frames, ep->maxframesize);
		} else {
			out_packet->packet_size[i] = 0;
		}
	}
```

and `snd_usb_queue_pending_output_urbs()` then assigns it straight onto the OUT URB's context:

```c
/* sound/usb/endpoint.c:492-497 — adopted onto the OUT URB with no clamp */
		/* copy over the length information */
		if (implicit_fb) {
			ctx->packets = packet->packets;      /* <-- destroys the allocated count */
			memcpy(ctx->packet_size, packet->packet_size,
			       packet->packets * sizeof(packet->packet_size[0]));
		}

		/* call the data handler to fill in playback data */
		err = prepare_outbound_urb(ep, ctx, in_stream_lock);
```

`ctx->packets` **is** the field that records how many `iso_frame_desc[]` slots the URB was allocated
with, so the original value is destroyed — there is no separate "allocated packets" member to clamp
against, and no `min()` is applied. `prepare_playback_urb()` then writes descriptors for
`i < ctx->packets`:

```c
/* sound/usb/pcm.c:1553-1560 — writes ctx->packets descriptors; the guard bounds BYTES, not i */
		for (i = 0; i < ctx->packets; i++) {
			counts = snd_usb_endpoint_next_packet_size(ep, ctx, i, avail);
			if (counts < 0 ||
			    (frames + counts) * stride > ctx->buffer_size)
				break;
			/* set up descriptor */
			urb->iso_frame_desc[i].offset = frames * stride;
			urb->iso_frame_desc[i].length = counts * stride;
```

**The `memcpy` above is safe** — both `ctx->packet_size[]` and `packet->packet_size[]` are
`int [MAX_PACKS_HS]` (48 entries) and `packet->packets <= 48`. The overflow is purely on
`urb->iso_frame_desc[]`.

**Why the existing guard does not save it.** The only bound in the loop is
`(frames + counts) * stride > ctx->buffer_size`, which caps the total *bytes*, not the number of
descriptors written. That is exactly the gap: the capture endpoint splits the *same audio byte rate*
into *more, smaller* packets than the playback endpoint, so the byte guard stays satisfied for every
one of the capture endpoint's packets while `i` runs far past the playback URB's allocated slot count.
With a playback URB allocated for 1 packet and a capture endpoint delivering 8, all 8 descriptors are
written — 7 × `sizeof(struct usb_iso_packet_descriptor)` = **112 bytes** written past the end of the
`struct urb` slab object, with attacker-influenced `offset` and `length` values.

**How the counts come to differ.** `urb_packs` for both endpoints is computed in `data_ep_set_params()`.
An IN endpoint, and any endpoint with `implicit_fb_sync`, takes this branch:

```c
if (usb_pipein(ep->pipe) || ep->implicit_fb_sync) {
        urb_packs = min(max_packs_per_urb, packs_per_ms);
        while (urb_packs > 1 && urb_packs * maxsize >= ep->cur_period_bytes)
                urb_packs >>= 1;
        ep->nurbs = MAX_URBS;
```

with `packs_per_ms = 8 >> ep->datainterval` and
`max_packs_per_urb = max(1u, MAX_PACKS_HS >> ep->datainterval)` at high speed. `ep->datainterval` comes
from `fmt->datainterval`, i.e. the altsetting's `bInterval` (`snd_usb_parse_datainterval()` clamps
`bInterval` to 1..4, giving `datainterval` 0..3) — **and the capture and playback altsettings carry
independent `bInterval` values**. So:

- capture altsetting with `bInterval = 1` → `datainterval = 0` → `urb_packs = min(48, 8) = 8`;
- playback altsetting with `bInterval = 4` → `datainterval = 3` → `urb_packs = min(6, 1) = 1`.

Nothing device-specific is required beyond that: implicit feedback is negotiated generically for UAC2
via `USB_ENDPOINT_USAGE_IMPLICIT_FB` in `sound/usb/implicit.c`, with **no VID/PID quirk needed**.

A second, independent route uses the `while (urb_packs > 1 && urb_packs * maxsize >= ep->cur_period_bytes)`
loop: `cur_period_bytes` derives from the ALSA period size chosen by userspace in `hw_params`, so a
small playback period drives the playback `urb_packs` down to 1 while the capture endpoint (different
`maxsize`, different period accounting) keeps 8.

The resulting primitive is a linear slab overflow immediately past a `struct urb` allocation, written as
pairs of `unsigned int` (`offset`, `length`) at 16-byte stride. Both values are influenced by the device
(via the capture endpoint's per-packet `actual_length`) and by the ALSA stream geometry, so the attacker
has substantial control over the written content as well as over the source allocation's kmalloc bucket
(the `struct urb` size is a function of `u->packets`). It repeats on every URB completion, making
grooming easy. `struct urb` lives in a general kmalloc cache alongside many other objects, and the
overflow is deterministic once the descriptors are chosen.

## Trigger

1. Present a UAC2 composite audio device — physically attached, or emulated by any programmable
   gadget — with:
   - a playback (OUT) isochronous endpoint whose class-specific endpoint descriptor marks it as using
     implicit feedback from the capture endpoint (`USB_ENDPOINT_USAGE_IMPLICIT_FB` on the IN endpoint,
     which `snd_usb_implicit_fb_set_params()` / `implicit.c` recognises generically), and whose
     audio-streaming altsetting declares **`bInterval = 4`**;
   - a capture (IN) isochronous endpoint in an altsetting declaring **`bInterval = 1`**.
   No vendor/product ID match is needed.
2. From userspace, open the playback PCM device, run `SNDRV_PCM_IOCTL_HW_PARAMS` with the advertised
   rate/format/channels. `data_ep_set_params()` allocates the playback URBs with
   `usb_alloc_urb(1, ...)` and the capture/sync URBs with `usb_alloc_urb(8, ...)`.
3. `SNDRV_PCM_IOCTL_PREPARE` and `SNDRV_PCM_IOCTL_START`, then write audio.
4. On each capture URB completion, `snd_usb_handle_sync_urb()` enqueues a packet info with
   `packets = 8`. `snd_usb_queue_pending_output_urbs()` sets `ctx->packets = 8` on a playback URB
   allocated for 1 packet, and `prepare_playback_urb()` writes `iso_frame_desc[0..7]`, corrupting
   112 bytes past the `struct urb` allocation. This repeats on every URB for the life of the stream.
5. The corrupting values are `offset = frames * stride` and `length = counts * stride`, where `counts`
   is derived from the device-supplied `iso_frame_desc[i].actual_length` of the capture URB
   (`endpoint.c:1826`) — i.e. the overwritten content is device-controlled within a wide range.

The attacker-controlled input is the peripheral's descriptors plus its per-packet `actual_length`.
There is no `capable()` / `ns_capable()` check anywhere on the path from `snd_pcm_ioctl` to
`endpoint.c:494` / `pcm.c:1553`: no `CAP_SYS_ADMIN` and no `CAP_NET_ADMIN` are required, and opening
the PCM node needs only the usual audio group / desktop ACL access.

`CONFIG_SND_USB_AUDIO` must be enabled for the code to be built at all; it is set in the common
distribution configurations.
