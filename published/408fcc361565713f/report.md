# ceph: out-of-bounds read in `ceph_handle_snap()`

|  |  |
|---|---|
| Bug class | out-of-bounds read (below the allocation) / integer sign-extension |
| Subsystem | `fs/ceph` |
| Location | `fs/ceph/snap.c:1147` (`ceph_handle_snap()`) |

## Root cause

`num_split_inos` and `num_split_realms` are declared as signed `int`:

```c
/* fs/ceph/snap.c:1030 — signed, though the wire fields are __le32 */
	int num_split_inos, num_split_realms;
	...
/* fs/ceph/snap.c:1046 */
	num_split_inos = le32_to_cpu(h->num_split_inos);
	num_split_realms = le32_to_cpu(h->num_split_realms);
```

and are then used in pointer arithmetic:

```c
/* fs/ceph/snap.c:1067 — SPLIT arm: sign-extended multiply, then an ineffective check */
		split_inos = p;
		p += sizeof(u64) * num_split_inos;
		split_realms = p;
		p += sizeof(u64) * num_split_realms;
		ceph_decode_need(&p, e, sizeof(*ri), bad);
		ri = p;
```

`sizeof(u64)` is `size_t`, so a negative `int` is **sign-extended** to 64 bits before the multiply.
`num_split_inos = 0xFFFFFF00` is `-256` as an `int`, so `p += 8 * (size_t)(-256)` moves `p`
**2048 bytes backwards**, before the start of `msg->front.iov_base`.

The `ceph_decode_need()` that follows cannot catch this. `ceph_has_room()`
(`include/linux/ceph/decode.h:52`) is:

```c
/* include/linux/ceph/decode.h:52 — upper bound only; a pointer below the buffer passes */
static inline bool ceph_has_room(void **p, void *end, size_t n)
{
	return end >= *p && n <= end - *p;
}
```

Both conditions hold comfortably when `*p` is *below* the buffer — `end >= *p` is true, and
`end - *p` is a large positive number. The check is designed to catch overshoot past `end`; it has
no notion of a lower bound. The two `for (i = 0; i < num_split_inos; i++)` loops (`:1083`, `:1127`)
never execute with a negative bound, so nothing else notices either.

`ri = p` then reads `struct ceph_mds_snap_realm` from below the allocation, and the displaced `p` is
handed on to the snap trace parser:

```c
	if (ceph_update_snap_trace(mdsc, p, e,
				   op == CEPH_SNAP_OP_DESTROY,
				   NULL)) {
```

which does its own `ceph_decode_need(&p, e, sizeof(*ri), bad); ri = p;` — passing for the same
reason — and dereferences `ri->ino`, `ri->seq`, `ri->parent`, `ri->parent_since`, `ri->num_snaps`
and `ri->num_prior_parent_snaps`, all out of bounds.

`num_split_inos = 0x80000000` gives `INT_MIN`, i.e. `p` moves 16 GiB below the buffer — a wild
pointer dereference rather than a mere slab underread.

The non-SPLIT arm at `:1147-1148` repeats the same arithmetic and has **no** `ceph_decode_need()`
after it at all:

```c
/* fs/ceph/snap.c:1147 — non-SPLIT arm: no check at all */
		p += sizeof(u64) * num_split_inos;
		p += sizeof(u64) * num_split_realms;
```

so a plain `CEPH_SNAP_OP_UPDATE` reaches `ceph_update_snap_trace()` with the displaced pointer
directly.

The function does validate its fixed header (`if (msg->front.iov_len < sizeof(*h)) goto bad;` at
`:1040`), and a *positive* overshoot of `num_split_inos` **is** correctly caught by the
`ceph_decode_need()` at `:1070`. Only the sign-extension path slips through, and only because the
counts were declared `int` rather than `u32` — the wire fields themselves are `__le32`.

The primitive is an out-of-bounds **read** at an attacker-chosen negative offset (from a few bytes
to ~16 GiB below the `msg->front` allocation). The values read are used to look up / create snap
realms and set `realm->seq`, `realm->created`, `realm->parent_since` — so a small, precisely
controlled underread is an information-influence channel, while a large one is a straightforward
oops.

## Trigger

1. The victim has a CephFS mount. The attacker is the MDS peer: a malicious or compromised MDS,
   address takeover, or an on-path attacker (default msgr2 `crc` mode has no encryption).
2. The MDS sends a `CEPH_MSG_CLIENT_SNAP` message with a `struct ceph_mds_snap_head` whose
   `num_split_inos = 0xFFFFFF00` (i.e. `-256`).
3. **Non-SPLIT path (simplest):** set `op = CEPH_SNAP_OP_UPDATE`. `:1147` moves `p` 2048 bytes below
   `msg->front.iov_base`, with no check at all, and `:1155` hands it to
   `ceph_update_snap_trace()`, which reads a `struct ceph_mds_snap_realm` from there.
4. **SPLIT path:** set `op = CEPH_SNAP_OP_SPLIT`. `:1068` displaces `p`; the
   `ceph_decode_need(&p, e, sizeof(*ri), bad)` at `:1070` passes because `ceph_has_room()` only
   guards the upper bound; `ri = p` reads out of bounds immediately.
5. Scaling `num_split_inos` toward `0x80000000` turns the slab underread into an unmapped-address
   dereference and a hard oops.

One message reaches the bug, with no victim-side action required beyond having the mount. No local
account and no local capability on the victim is required by the attacker. The victim's CephFS
mount needs `CAP_SYS_ADMIN` in the initial user namespace, and the code is built only with
`CONFIG_CEPH_FS` / `CONFIG_CEPH_LIB` enabled.
