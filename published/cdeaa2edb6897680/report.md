# net/ipv6: out-of-bounds skb access in udpv6_queue_rcv_skb()

|  |  |
|---|---|
| Bug class | Out-of-bounds skb pointer/length corruption (reported by KASAN as a slab-use-after-free read) |
| Subsystem | net/ipv6 |
| Location | `net/ipv6/udp.c:890-909` (`udpv6_queue_rcv_skb()`) |

## Root cause

`udpv6_queue_rcv_skb()` handles an unexpected UDP GSO skb by pushing back to the
MAC header using `-skb_mac_offset(skb)`, without verifying that an L2 header
exists.

```c
if (likely(!udp_unexpected_gso(sk, skb)))
        return udpv6_queue_rcv_one_skb(sk, skb);

__skb_push(skb, -skb_mac_offset(skb));
segs = udp_rcv_segment(sk, skb, false);
```

SRv6 End.DT6 VRF decapsulation calls `skb_unset_mac_header()`. Outer IP-in-IPv6
GSO state is removed by `iptunnel_pull_offloads()`, but an inner UDP L4/fraglist
GSO type may remain. Delivery to a normal IPv6 UDP socket makes
`udp_unexpected_gso()` true. The unset MAC sentinel turns `skb_mac_offset()`
into a large value, and its negation wraps when passed to `__skb_push()`, moving
skb pointers outside their allocation.

The conflicting assumptions along the receive path:

- `net/ipv6/seg6_local.c:end_dt_vrf_rcv()` unsets `skb->mac_header` before
  invoking the VRF receive handler.
- `drivers/net/vrf.c:vrf_ip6_rcv()` rebuilds the MAC header only when a packet
  tap is attached to the VRF (`!list_empty(&vrf_dev->ptype_all)`). With no
  sniffer, the unset `u16` sentinel (`0xffff`) reaches UDP.
- `iptunnel_pull_offloads()` clears encapsulation GSO bits but preserves
  `SKB_GSO_UDP_L4`/`SKB_GSO_FRAGLIST`.
- A normal UDP socket rejects those GSO forms through `udp_unexpected_gso()`.
  `udpv6_queue_rcv_skb()` then passes the negated sentinel-derived MAC offset to
  unsigned `__skb_push()`, corrupting `skb->data` and `skb->len` before
  segmentation.

The KASAN classification is incidental to where the sentinel-corrupted data
pointer landed: the root cause is the unset `mac_header` arithmetic in
`udpv6_queue_rcv_skb()`, which moves `skb->data` roughly 4 GiB before its
allocation. The resulting primitive is skb pointer/length corruption followed by
segmentation, likely causing an out-of-bounds access and kernel DoS.

## Trigger

The bug is reached on the IPv6 UDP receive path after SRv6 End.DT6/VRF
decapsulation:

1. Configure SRv6 End.DT6 into a VRF with an IPv6 UDP listener and GRO enabled.
2. Do not enable UDP GRO/fraglist acceptance on the destination socket.
3. Send an IPv6-in-IPv6/SRv6 UDP flow that arrives as an inner `SKB_GSO_UDP_L4`
   or `SKB_GSO_FRAGLIST` skb after decapsulation.
4. End.DT6 explicitly unsets `mac_header` and delivers the GSO skb through IPv6
   to UDP.
5. `udpv6_queue_rcv_skb()` executes the invalid `__skb_push()` before
   segmentation.

Privilege: configuring the SRv6 End.DT6 / VRF topology requires `CAP_NET_ADMIN`,
which can be held over an owned network namespace (`CLONE_NEWUSER |
CLONE_NEWNET`) rather than in the initial namespace. Once an administrator has
configured the topology, an ordinary remote sender needs no privilege to drive
the path.

Required build configuration: `CONFIG_IPV6=y`, `CONFIG_IPV6_SEG6_LWTUNNEL=y`,
`CONFIG_NET_VRF=y`, `CONFIG_NET_L3_MASTER_DEV=y`, and
`CONFIG_IPV6_MULTIPLE_TABLES=y`.
