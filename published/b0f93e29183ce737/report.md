# fs/ceph: slab out-of-bounds write in `decode_encrypted_symlink()`

|  |  |
|---|---|
| Bug class | slab out-of-bounds write (one byte) |
| Subsystem | fs/ceph |
| Location | `fs/ceph/inode.c`:958 (`decode_encrypted_symlink()`) |

## Root cause

Audited mainline commit `3cd8b194bf3428dfa53120fee47e827a7c495815`.
Allocation at `fs/ceph/inode.c`:946, out-of-bounds write at :958, caller at
:1231–1241; the decode is at `fs/ceph/mds_client.c`:131
(`parse_reply_info_in()`).

`parse_reply_info_in()` decodes the symlink target with an **upper bound only**:

```c
	ceph_decode_32_safe(p, end, info->symlink_len, bad);
	ceph_decode_need(p, end, info->symlink_len, bad);
	info->symlink = *p;
```

`symlink_len == 0` is accepted, and `info->symlink` is a valid pointer to zero bytes. For an
encrypted inode, `ceph_fill_inode()` passes that straight through:

```c
	err = decode_encrypted_symlink(mdsc, iinfo->symlink, symlen, (u8 **)&sym);
```

and the callee does:

```c
	sym = kmalloc(enclen + 1, GFP_NOFS);        /* enclen == 0  ->  kmalloc(1) */
	...
	declen = base64_decode(encsym, enclen, sym, false, BASE64_IMAP);  /* returns 0 */
	if (declen < 0) { ... }
	sym[declen + 1] = '\0';                     /* sym[1] on a 1-byte object */
```

`base64_decode()` with `srclen == 0` never enters its `while (srclen >= 4)` loop and returns
`bp - dst == 0` (`lib/base64.c`). So `declen == 0` and the terminator is written to `sym[1]` —
**one byte past the end of a `kmalloc(1)` allocation**.

The `+ 1` is wrong for *every* length, not just zero: it writes the NUL one byte too far and
leaves `sym[declen]` uninitialised. For `enclen >= 2` the write still lands inside the
`enclen + 1` allocation (base64 shrinks 4→3), so only `enclen == 0` is an out-of-bounds write —
but the uninitialised `sym[declen]` affects all encrypted symlinks, and `sym` is stored as
`ci->i_symlink` and later consumed as a NUL-terminated string via `inode->i_link`, so the
missing terminator is itself a latent over-read.

**Why it is not already fixed**: the only length test on this path is
`if (symlen != i_size_read(inode))` at `inode.c:1231`, which merely `pr_err_client()`s and falls
through — unlike the non-encrypted branch below it, which corrects the length. There is no
`if (!symlen)` anywhere between `parse_reply_info_in()` and `decode_encrypted_symlink()`.

The relevant code, as upstream has it:

```c
/* fs/ceph/mds_client.c:~131 — parse_reply_info_in(): upper bound only */
	ceph_decode_32_safe(p, end, info->symlink_len, bad);
	ceph_decode_need(p, end, info->symlink_len, bad);
	info->symlink = *p;
	*p += info->symlink_len;

/* fs/ceph/inode.c:938-960 */
static int decode_encrypted_symlink(struct ceph_mds_client *mdsc,
				    const char *encsym,
				    int enclen, u8 **decsym)
{
	int declen;
	u8 *sym;

	sym = kmalloc(enclen + 1, GFP_NOFS);      /* enclen == 0 -> kmalloc(1) */
	if (!sym)
		return -ENOMEM;

	declen = base64_decode(encsym, enclen, sym, false, BASE64_IMAP);
	if (declen < 0) {
		...
		return -EIO;
	}
	sym[declen + 1] = '\0';                   /* <-- OOB write; also off-by-one
	                                                 for all lengths, leaving
	                                                 sym[declen] uninitialised */
	*decsym = sym;
	return declen;
}

/* fs/ceph/inode.c:1229-1241 — the caller only warns, never rejects */
			if (IS_ENCRYPTED(inode)) {
				if (symlen != i_size_read(inode))
					pr_err_client(cl,
						"%p %llx.%llx BAD symlink size %lld\n",
						inode, ceph_vinop(inode),
						i_size_read(inode));

				err = decode_encrypted_symlink(mdsc, iinfo->symlink,
							       symlen, (u8 **)&sym);
```

The resulting primitive is a one-byte heap overflow with a fixed value (`'\0'`) at a controlled
offset relative to a `kmalloc-8` object. A NUL-byte-overflow into an adjacent slab object is a
well-established corruption primitive (e.g. clobbering the low byte of an adjacent pointer or
size field) given heap grooming. The value is fixed and the target object must be groomed, but
the attacker controls timing and can repeat indefinitely. The accompanying uninitialised
`sym[declen]` additionally makes `i_symlink` non-terminated, a separate over-read.

## Trigger

1. Client mounts cephfs against a malicious or compromised MDS (or an attacker MITMs an
   unsigned/unencrypted msgr session). Requires `CONFIG_FS_ENCRYPTION` — otherwise the stub
   returns `-EOPNOTSUPP`.
2. Client performs any lookup or getattr that returns an inode.
3. MDS replies with an inode of type `S_IFLNK` that carries:
   - a **non-empty `fscrypt_auth` blob**, which makes `ceph_fill_inode()` set `S_ENCRYPTED`
     (`fs/ceph/inode.c:1088`) — this executes *before* the `S_IFLNK` branch, so `IS_ENCRYPTED()`
     is already true when the symlink is decoded; and
   - **`symlink_len = 0`**.
4. `decode_encrypted_symlink()` does `kmalloc(1)`, `base64_decode(…, 0, …) == 0`, then
   `sym[1] = '\0'` → one-byte heap overflow past a `kmalloc-8` object.

The write is taken in the ceph messenger work queue, on the path
`ceph_con_workfn()` → `ceph_con_v1_try_read()` → `mds_dispatch()` →
`ceph_fill_trace()` → `ceph_fill_inode()`. Reaching it involves no race and no
heap grooming: the reply is processed once and the out-of-bounds write follows
directly.

**Reachability**: Remote, from the ceph MDS. Requires a cephfs mount with
`CONFIG_FS_ENCRYPTION`. Mounting is `CAP_SYS_ADMIN`, but the *attacker* is the remote server,
not the mounting user. No privilege is required on the client; the attacker must be the ceph
MDS endpoint, and `mount(2)` is the victim's action.

**Configuration exposure**: `CONFIG_FS_ENCRYPTION=y` is required — with the option off, the
vulnerable body is not compiled at all and `ceph_fill_inode()` just logs "decoding encrypted
symlink failed: -95". It is the normal setting on real distributions (Debian, Ubuntu, Fedora,
RHEL and the Android/Chrome OS kernels all enable it, since ext4 and f2fs encryption depend on
it), so this is not an exotic configuration. `CONFIG_CEPH_FS` and `CONFIG_CEPH_LIB` must also
be built.
