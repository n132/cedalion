# cifs: out-of-bounds read in parse_reparse_native_symlink()

|  |  |
|---|---|
| Bug class | slab out-of-bounds read |
| Subsystem | fs/smb/client |
| Location | `fs/smb/client/reparse.c:1014` (`parse_reparse_native_symlink()`) |

## Root cause

On the SMB2 leg, `reparse_buf_ptr()` (`fs/smb/client/smb2inode.c:29-51`) guarantees exactly
`count >= sizeof(struct reparse_data_buffer)` (= 8) and `count >= rdlen + 8`, with
`off + count <= iov->iov_len`:

```c
	count = le32_to_cpu(io->OutputCount);
	off = le32_to_cpu(io->OutputOffset);
	if (check_add_overflow(off, count, &len) || len > iov->iov_len)
		return ERR_PTR(...);
	buf = (struct reparse_data_buffer *)((u8 *)io + off);
	len = sizeof(*buf);
	if (count < len)
		return ERR_PTR(...);
	rdlen = le16_to_cpu(buf->ReparseDataLength);
	if (count < rdlen + len)
		return ERR_PTR(...);
	return buf;
```

A server answering `FSCTL_GET_REPARSE_POINT` with `ReparseTag = IO_REPARSE_TAG_SYMLINK`,
`ReparseDataLength = 0`, `OutputCount = 8` and `OutputOffset = iov_len - 8` passes every one of
those gates with exactly **8** readable bytes. `parse_reparse_point()` then dispatches to
`parse_reparse_native_symlink(sym, plen = 8)`, whose first two statements read **past** that:

```c
/* fs/smb/client/reparse.c:1003 */
static int parse_reparse_native_symlink(struct reparse_symlink_data_buffer *sym,
				 u32 plen, ...)
{
	unsigned int len;
	unsigned int offs;

	/* We handle Symbolic Link reparse tag here. See: MS-FSCC 2.1.2.4 */

	offs = le16_to_cpu(sym->SubstituteNameOffset);   /* bytes 8..9  of an 8-byte buffer */
	len  = le16_to_cpu(sym->SubstituteNameLength);   /* bytes 10..11 */
	if (offs + 20 > plen || offs + len + 20 > plen) {  /* the check, one read too late */
		cifs_dbg(VFS, "srv returned malformed symlink buffer\n");
		return smb_EIO2(smb_eio_trace_reparse_native_sym_len,
				offs << 16 | len, plen);
	}
	...
}
```

The bound check at line 1016 is correct — but it runs *after* the 4 bytes have already been read,
and the out-of-bounds values are then passed into
`smb_EIO2(smb_eio_trace_reparse_native_sym_len, offs << 16 | len, plen)`, i.e. recorded in a
tracepoint. Bytes guaranteed: 8. Bytes consumed before any check: 12.

The three sibling handlers in the same file get this right: `parse_reparse_nfs()`
(`reparse.c:741`) checks `len < sizeof(buf->InodeType)` *before* touching `InodeType`, and
`parse_reparse_wsl_symlink()` checks `len > data_offset` before reading `Version`. Only the
`IO_REPARSE_TAG_SYMLINK` arm reads first and checks second:

```c
/* fs/smb/client/reparse.c:741 */
static int parse_reparse_nfs(struct reparse_nfs_data_buffer *buf, ...)
{
	len = le16_to_cpu(buf->ReparseDataLength);
	if (len < sizeof(buf->InodeType)) {          /* checked BEFORE the read */
		cifs_dbg(VFS, "srv returned malformed nfs buffer\n");
		return smb_EIO2(smb_eio_trace_reparse_nfs_too_short,
				len, sizeof(buf->InodeType));
	}
	...
}
```

The consequence is a 4-byte read past the region `reparse_buf_ptr()` validated. The values are
recorded in a tracepoint (`smb_EIO2`) and otherwise discarded, so there is no exfiltration path
and no write.

## Trigger

The attacker is a malicious or MITM'd SMB2/3 server against a client that mounts it. No local
privilege beyond having the mount is required; any `stat`/`lookup` of a reparse point drives the
path. This needs only SMB2/3 — no `CONFIG_CIFS_ALLOW_INSECURE_LEGACY` and no SMB1. Built whenever
`CONFIG_CIFS=y`.

1. Victim mounts the server (SMB2 or SMB3).
2. Victim `stat`s a path the server marks as a reparse point, driving
   `reparse_info_to_fattr()` → `smb2_get_reparse_point_buffer()` → `reparse_buf_ptr()`.
3. Reply to `FSCTL_GET_REPARSE_POINT` with `OutputCount = 8`, `OutputOffset = iov_len - 8`, so the
   8-byte `struct reparse_data_buffer` sits flush against the end of the validated region, and set
   `ReparseTag = IO_REPARSE_TAG_SYMLINK`, `ReparseDataLength = 0`.
4. All of `reparse_buf_ptr()`'s checks pass with exactly 8 bytes available.
5. `parse_reparse_native_symlink()` reads `sym->SubstituteNameOffset` and
   `sym->SubstituteNameLength` at offsets 8-11 — 4 bytes past the validated region — before line
   1016 rejects the buffer.

The client trusts the server-supplied `OutputOffset`/`OutputCount` framing; the overread is of
whatever follows the validated region in the receive buffer.
