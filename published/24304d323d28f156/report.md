# ALSA ua101: slab out-of-bounds write in playback_work() / start_usb_playback()

|  |  |
|---|---|
| Bug class | slab out-of-bounds write (coherent-DMA/heap buffer overflow) |
| Subsystem | sound/usb/misc |
| Location | `sound/usb/misc/ua101.c:281-290` (`playback_work()`), `ua101.c:583-586` (`start_usb_playback()`) |

## Root cause

The playback URB buffer is sized from one endpoint descriptor and the transfer length is
computed from a *different* endpoint descriptor, with no relation enforced between them.
The length is recomputed on every completion from state belonging to another endpoint.

`alloc_stream_urbs()` carves each playback URB's `transfer_buffer` out of the coherent buffers in
slices of exactly `stream->max_packet_bytes`, and fixes both `transfer_buffer_length` and
`iso_frame_desc[0].length` to that value:

```c
/* sound/usb/misc/ua101.c:1058-1090 — the slice is sized by the PLAYBACK endpoint */
static int alloc_stream_urbs(struct ua101 *ua, struct ua101_stream *stream,
			     void (*urb_complete)(struct urb *))
{
	unsigned max_packet_size = stream->max_packet_bytes;
	...
		while (size >= max_packet_size) {
			...
			urb->urb.transfer_buffer = addr;
			urb->urb.transfer_buffer_length = max_packet_size;
			urb->urb.iso_frame_desc[0].length = max_packet_size;
			...
			addr += max_packet_size;
```

For the playback stream that is `ua->playback.max_packet_bytes = usb_endpoint_maxp(playback epd)`.

The length actually written into that slice comes from the **capture** endpoint:

```c
/* sound/usb/misc/ua101.c:357-381 — frames comes from the CAPTURE endpoint */
	if (urb->status >= 0 && urb->iso_frame_desc[0].status >= 0)
		frames = urb->iso_frame_desc[0].actual_length /
			stream->frame_bytes;                          /* capture.frame_bytes */
	else
		frames = 0;
	...
			ua->rate_feedback[write_ptr] = frames;

/* sound/usb/misc/ua101.c:281-293 — and is used as a PLAYBACK length, then written */
			frames = ua->rate_feedback[ua->rate_feedback_start];
			...
			urb->urb.iso_frame_desc[0].length =
				frames * ua->playback.frame_bytes;            /* playback.frame_bytes */
			if (test_bit(ALSA_PLAYBACK_RUNNING, &ua->states))
				do_period_elapsed |= copy_playback_data(&ua->playback,
									&urb->urb,
									frames);
			else
				memset(urb->urb.transfer_buffer, 0,
				       urb->urb.iso_frame_desc[0].length);

			/* and off you go ... */
			err = usb_submit_urb(&urb->urb, GFP_ATOMIC);   /* too late */
```

So the bytes written are

    frames * playback.frame_bytes
      = (capture_actual_length / capture.frame_bytes) * playback.frame_bytes

into a slice sized `playback.max_packet_bytes`. **Four independent, device-declared quantities** feed
this, and `detect_usb_format()` relates none of the relevant pairs:

```c
/* sound/usb/misc/ua101.c:976-1004 — what detect_usb_format() does and does not check */
	if (fmt_capture->bSubframeSize != fmt_playback->bSubframeSize) { ... return -ENXIO; }
	...
	ua->capture.channels  = fmt_capture->bNrChannels;
	ua->playback.channels = fmt_playback->bNrChannels;
	if (!ua->capture.channels || !ua->playback.channels) { ... return -EINVAL; }

	ua->capture.frame_bytes  = fmt_capture->bSubframeSize  * ua->capture.channels;
	ua->playback.frame_bytes = fmt_playback->bSubframeSize * ua->playback.channels;

	epd = &ua->intf[INTF_CAPTURE]->altsetting[1].endpoint[0].desc;
	if (!usb_endpoint_is_isoc_in(epd) || usb_endpoint_maxp(epd) == 0) { ... }
	ua->capture.max_packet_bytes = usb_endpoint_maxp(epd);

	epd = &ua->intf[INTF_PLAYBACK]->altsetting[1].endpoint[0].desc;
	if (!usb_endpoint_is_isoc_out(epd) || usb_endpoint_maxp(epd) == 0) { ... }
	ua->playback.max_packet_bytes = usb_endpoint_maxp(epd);
	/* no comparison of the two channel counts, and none of the two wMaxPacketSizes */
```

The validation performed is: `bSubframeSize` must be 3 or 4 **and must match** between the two
interfaces; `bBitResolution` must be 24 on both; `tSamFreq` must match. `bNrChannels` is checked only
for being non-zero and is **never compared between capture and playback**; the two `wMaxPacketSize`
values are checked only for being non-zero and are **never compared to each other**. So both ratios
`capture.max_packet_bytes / capture.frame_bytes` and `playback.frame_bytes / playback.max_packet_bytes`
are freely device-chosen.

Worked example: capture declares `bNrChannels = 2`, `bSubframeSize = 4` (`capture.frame_bytes = 8`) with
`wMaxPacketSize = 1024`; playback declares `bNrChannels = 8`, `bSubframeSize = 4`
(`playback.frame_bytes = 32`) with `wMaxPacketSize = 64`. A full capture packet gives
`frames = 1024 / 8 = 128`, so the write is `128 * 32 = 4096` bytes into a **64-byte** slice — roughly
4 KB past the slice and past the end of the `usb_alloc_coherent()` page it belongs to.
(`ua->rate_feedback[]` is `u8 [MAX_QUEUE_LENGTH]`, so `frames` is truncated mod 256 on the way through
— it caps the multiplier but does not prevent the overflow; even `frames = 1` overflows when
`playback.frame_bytes > playback.max_packet_bytes`.)

**Why this is not already fixed.** There is no `min()` of `frames` against
`playback.max_packet_bytes / playback.frame_bytes` anywhere, no comparison of the two endpoints'
`wMaxPacketSize`, and no channel-count equality check in `detect_usb_format()`. `sound/usb/validate.c`
never sees these descriptors — ua101 parses `alts->extra` itself in `find_format_descriptor()`.
Crucially, `usb_submit_urb()` **cannot** save this: it would reject the over-long
`iso_frame_desc[0].length` with `-EMSGSIZE`, but it is called at `ua101.c:293`, *after* the `memset()`
and `copy_playback_data()` have already written out of bounds.

The content written by `copy_playback_data()` is taken straight from `runtime->dma_area`, i.e. **PCM
samples supplied by userspace** — so the overflowing bytes are attacker-chosen:

```c
/* sound/usb/misc/ua101.c:207-226 — the overflowing copy, content from userspace */
static bool copy_playback_data(struct ua101_stream *stream, struct urb *urb,
			       unsigned int frames)
{
	...
	frame_bytes = stream->frame_bytes;
	source = runtime->dma_area + stream->buffer_pos * frame_bytes;
	if (stream->buffer_pos + frames <= runtime->buffer_size) {
		memcpy(urb->transfer_buffer, source, frames * frame_bytes);
	} else {
		frames1 = runtime->buffer_size - stream->buffer_pos;
		memcpy(urb->transfer_buffer, source, frames1 * frame_bytes);
		memcpy(urb->transfer_buffer + frames1 * frame_bytes,
		       runtime->dma_area, (frames - frames1) * frame_bytes);
	}
```

The resulting primitive is a linear overflow of a coherent DMA buffer by up to several kilobytes, with
the overflowing bytes taken verbatim from the userspace PCM ring — i.e. **fully attacker-chosen
content** at an attacker-chosen length, repeated on every playback URB. The `memset()` variant at
`ua101.c:584-586` gives the same overflow with zero bytes and requires no PCM writer at all. Content,
length and repetition rate are all controlled, and the target is page-allocator/dma-pool memory
adjacent to other kernel allocations. The overflow happens on the CPU side (`memcpy`/`memset`), so it
is KASAN-visible — but equally it is a straightforward adjacent-object overwrite in production kernels.

## Trigger

1. Present a USB device matching one of ua101's IDs — `0x0582:0x0044` (UA-1000), `0x0582:0x007d`
   (UA-101 HS) or `0x0582:0x008d` (UA-101 FS). No physical Roland hardware is needed.
2. In the descriptors, expose the capture and playback interfaces ua101 expects, with:
   - matching `bSubframeSize` (4) and `bBitResolution` (24) and matching `tSamFreq` — these are the only
     cross-checks the driver performs;
   - capture interface altsetting 1: isoc IN endpoint with a large `wMaxPacketSize` (e.g. 1024) and a
     format descriptor declaring `bNrChannels = 2`;
   - playback interface altsetting 1: isoc OUT endpoint with a small `wMaxPacketSize` (e.g. 64) and a
     format descriptor declaring `bNrChannels = 8`.
3. `snd_usb_ua101` probes and creates the PCM devices.
4. Open the playback PCM, `HW_PARAMS`/`PREPARE`/`START`, and write PCM data (the payload that will land
   out of bounds). Also start capture, or simply let `start_usb_playback()` run — the silence path at
   `ua101.c:584-586` does the same `memset()` with the same unchecked length.
5. On each capture URB completion, the emulated device returns a full-size IN packet. `frames` becomes
   128, `playback_work()` computes a 4096-byte length and `copy_playback_data()` memcpys 4096 bytes of
   userspace-supplied audio into a 64-byte slice of a coherent DMA buffer.

Merely `open()`ing `/dev/snd/pcmC0D0p` triggers it: `playback_pcm_open()` →
`start_usb_capture()` → `start_usb_playback()`. No `HW_PARAMS`/`PREPARE`/`START` and no
PCM writer are needed; this is the "silence" `memset()` variant at `ua101.c:584-586`.
The `copy_playback_data()` variant is the same arithmetic with userspace-supplied bytes.

Reachability is probe-time descriptor choice plus opening the playback PCM node. No `capable()` /
`ns_capable()` check sits on the path from the PCM node to the buggy line; the overflow itself happens
inside `open()`. Spoofing a Roland VID/PID is free for an emulated device.

`CONFIG_SND_USB_UA101` must be set for the driver to be built at all. The bug is reachable on any
kernel that ships `snd-usb-ua101` (built-in or as a module, which is the normal distro configuration,
e.g. Debian/Ubuntu ship `snd-usb-ua101.ko` and it is auto-loaded by the `usb:v0582p007D*` modalias).
