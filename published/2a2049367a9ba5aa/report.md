# ceph: NULL-pointer dereference in `handle_cap_grant()`

|  |  |
|---|---|
| Bug class | NULL pointer dereference (a `kref_get()` write through a NULL pointer) |
| Subsystem | fs/ceph (libceph messenger) |
| Location | `fs/ceph/caps.c:3671-3685` (`handle_cap_grant()`) |

## Root cause

`handle_cap_grant()` installs a new xattr blob when the MDS says the message carries one:

```c
/* fs/ceph/caps.c:3671-3685 */
	if ((extra_info->issued & CEPH_CAP_XATTR_EXCL) == 0 &&
	    grant->xattr_len) {
		int len = le32_to_cpu(grant->xattr_len);
		u64 version = le64_to_cpu(grant->xattr_version);

		if (version > ci->i_xattrs.version) {
			doutc(cl, " got new xattrs v%llu on %p %llx.%llx len %d\n", ...);
			if (ci->i_xattrs.blob)
				ceph_buffer_put(ci->i_xattrs.blob);
			ci->i_xattrs.blob = ceph_buffer_get(xattr_buf);   /* xattr_buf may be NULL */
			ci->i_xattrs.version = version;
			...
		}
	}
```

`xattr_buf` is `msg->middle`, passed by both call sites:

```c
/* fs/ceph/caps.c:4596-4597 and 4628-4629 */
		handle_cap_grant(inode, session, cap, h, msg->middle, &extra_info);
```

The decision to gate on `grant->xattr_len` — a field of the **front** — is the bug: the middle
buffer's existence is governed by an entirely independent header field, `middle_len`:

```c
/* net/ceph/messenger.c:2100-2108 */
	memcpy(&con->in_msg->hdr, hdr, sizeof(*hdr));

	if (middle_len && !con->in_msg->middle) {
		ret = ceph_alloc_middle(con, con->in_msg);
		...
	}
```

With `middle_len == 0` no middle is ever allocated, so `msg->middle` is NULL. And the accessor does
not defend itself, unlike its immediate sibling in the same header:

```c
/* include/linux/ceph/buffer.h:25-34 */
static inline struct ceph_buffer *ceph_buffer_get(struct ceph_buffer *b)
{
	kref_get(&b->kref);          /* no NULL check */
	return b;
}

static inline void ceph_buffer_put(struct ceph_buffer *b)
{
	if (b)                       /* the sibling DOES check */
		kref_put(&b->kref, ceph_buffer_release);
}
```

`kref_get()` is a `refcount_inc()`, i.e. a read-modify-write at offset 0 of a NULL pointer — a
NULL-pointer dereference in the messenger workqueue.

The peer installer of the same blob gets it right by construction:
`ceph_fill_inode()` (`fs/ceph/inode.c:1230-1238`) allocates its own
`ceph_buffer_new(iinfo->xattr_len)` from front data that `parse_reply_info_in()` has already
length-validated, rather than adopting a buffer whose existence is governed by a different field.

`ceph_handle_caps()` validates only `msg->front.iov_len < sizeof(*h)` — it never inspects
`msg->middle` — and no code between the messenger and `handle_cap_grant()` ties `xattr_len` to
`middle_len`. Note also that a *short* middle is survivable (`__build_xattrs()` uses
`blob->vec.iov_len`); only NULL is fatal.

## Trigger

1. Client has a cephfs mount with an established MDS session and at least one inode with a cap.
2. A malicious or compromised MDS sends `CEPH_MSG_CLIENT_CAPS` for that inode with:
   - `op = CEPH_CAP_OP_GRANT` (or `CEPH_CAP_OP_IMPORT`, which reaches the same code at
     `caps.c:4597`),
   - a valid, correctly sized front,
   - `h->xattr_len = 1` and `h->xattr_version = 1` (`ci->i_xattrs.version` starts at 0, so the
     `version > ci->i_xattrs.version` gate is trivially satisfied),
   - header `middle_len = 0`.
3. `ceph_con_in_msg_alloc()` skips the middle allocation, so `msg->middle == NULL`.
4. `ceph_handle_caps()` → `handle_cap_grant(..., msg->middle, ...)` →
   `ceph_buffer_get(NULL)` → `refcount_inc()` on address 0 → oops.

The client must not already hold `CEPH_CAP_XATTR_EXCL` on the inode, which is the normal state for
an inode the MDS is granting caps on.

**Reachability and privilege**: remote, from a malicious/compromised Ceph MDS (or an on-path
attacker able to MITM the MDS connection), via a single `CEPH_MSG_CLIENT_CAPS` on an established
session. No local privilege is required. The whole path runs in the `ceph-msgr` worker. On a kernel
with a non-zero `mmap_min_addr` — the default everywhere — address 0 is unmappable, so the write
faults and the result is an oops / DoS rather than a usable primitive. The trigger is deterministic:
one header field and one front field, no race, no grooming.

**Configuration**: requires `CONFIG_CEPH_FS` / `CONFIG_CEPH_LIB` for the code to be built.
