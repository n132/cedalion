# ipv6/seg6: per-CPU `srh_state->srh` dangles across `bpf_skb_pull_data()`, giving a 1-byte UAF write in `seg6_bpf_has_valid_srh()`

|  |  |
|---|---|
| Bug class | slab use-after-free (1-byte write + ~56-byte read) |
| Subsystem | net/ipv6 (SRv6 `End.BPF`) |
| Location | `net/ipv6/seg6_local.c`:1390–1412 (`seg6_bpf_has_valid_srh()`), reached from `input_action_end_bpf()` |

## Root cause

A raw pointer into a container is cached in state that outlives a call which may
move or free that container, and is then used without being re-derived. Here the
container is `skb->head` and the cached pointer is the per-CPU `srh_state->srh`.

`input_action_end_bpf()` caches a raw pointer into the packet buffer in per-CPU state and then runs
an arbitrary BPF program:

```c
/* net/ipv6/seg6_local.c — input_action_end_bpf(): cache, run program, then use the cache */
	local_lock_nested_bh(&seg6_bpf_srh_states.bh_lock);
	srh_state = this_cpu_ptr(&seg6_bpf_srh_states);
	srh_state->srh = srh;                 /* raw pointer into skb->head */
	srh_state->hdrlen = srh->hdrlen << 3;
	srh_state->valid = true;

	rcu_read_lock();
	bpf_compute_data_pointers(skb);
	ret = bpf_prog_run_save_cb(slwt->bpf.prog, skb);
	rcu_read_unlock();
	...
	if (srh_state->srh && !seg6_bpf_has_valid_srh(skb))    /* uses the cached pointer */
		goto drop;
```

The three seg6-specific helpers all re-derive the cached pointer after their own reallocations,
which establishes the invariant beyond doubt — e.g. `bpf_lwt_seg6_adjust_srh()`:

```c
/* net/core/filter.c */
	if (ipv6_find_hdr(skb, &srhoff, IPPROTO_ROUTING, NULL, NULL) < 0)
		return -EINVAL;
	srh_state->srh = (struct ipv6_sr_hdr *)(skb->data + srhoff);   /* re-derived */
	srh_state->hdrlen += len;
	srh_state->valid = false;
```

`bpf_lwt_seg6_store_bytes()` does the same. **But the program is not limited to those helpers.**
`lwt_seg6local_func_proto()` falls through to `lwt_out_func_proto()` for anything it does not handle,
and that returns `&bpf_skb_pull_data_proto`:

```c
/* net/core/filter.c:8886 */
lwt_seg6local_func_proto(enum bpf_func_id func_id, const struct bpf_prog *prog)
{
	switch (func_id) {
#if IS_ENABLED(CONFIG_IPV6_SEG6_BPF)
	case BPF_FUNC_lwt_seg6_store_bytes:  return &bpf_lwt_seg6_store_bytes_proto;
	case BPF_FUNC_lwt_seg6_action:       return &bpf_lwt_seg6_action_proto;
	case BPF_FUNC_lwt_seg6_adjust_srh:   return &bpf_lwt_seg6_adjust_srh_proto;
#endif
	default:
		return lwt_out_func_proto(func_id, prog);   /* -> bpf_skb_pull_data_proto */
	}
}
```

`bpf_skb_pull_data()` reallocates the packet head and knows nothing about `srh_state`:

```c
/* net/core/filter.c, net/core/skbuff.c */
BPF_CALL_2(bpf_skb_pull_data, struct sk_buff *, skb, u32, len)
{
	return bpf_try_make_writable(skb, len ? : skb_headlen(skb));
}
/* -> __bpf_try_make_writable -> skb_ensure_writable: */
int skb_ensure_writable(struct sk_buff *skb, unsigned int write_len)
{
	if (!pskb_may_pull(skb, write_len))
		return -ENOMEM;
	if (!skb_cloned(skb) || skb_clone_writable(skb, write_len))
		return 0;
	return pskb_expand_head(skb, 0, 0, GFP_ATOMIC);   /* frees the old skb->head */
}
```

`bpf_try_make_writable()` calls `bpf_compute_data_pointers(skb)` afterwards, which fixes up the
program's own `data`/`data_end`, but nothing fixes up `srh_state->srh`.

Back in `input_action_end_bpf()`, `srh_state->srh` is non-NULL (stale) and, if the program also
called `adjust_srh`/`store_bytes` into the TLV area, `srh_state->valid` is `false`. That takes the
write branch of `seg6_bpf_has_valid_srh()`:

```c
/* net/ipv6/seg6_local.c:1390 */
bool seg6_bpf_has_valid_srh(struct sk_buff *skb)
{
	struct seg6_bpf_srh_state *srh_state = this_cpu_ptr(&seg6_bpf_srh_states);
	struct ipv6_sr_hdr *srh = srh_state->srh;     /* stale after pskb_expand_head() */

	lockdep_assert_held(&srh_state->bh_lock);
	if (unlikely(srh == NULL))
		return false;

	if (unlikely(!srh_state->valid)) {
		if ((srh_state->hdrlen & 7) != 0)
			return false;

		srh->hdrlen = (u8)(srh_state->hdrlen >> 3);                    /* UAF WRITE */
		if (!seg6_validate_srh(srh, (srh->hdrlen + 1) << 3, true))     /* UAF READ  */
			return false;

		srh_state->valid = true;
	}
	return true;
}
```

The written byte is `srh_state->hdrlen >> 3`, and `hdrlen` is under the program's control through
`bpf_lwt_seg6_adjust_srh()`'s `len` argument — so the attacker chooses the value. `seg6_validate_srh()`
then reads roughly 56 further bytes of freed memory, and its verdict decides drop-versus-forward,
which makes it a coarse oracle on the freed contents.

The resulting primitive is a **1-byte write of an attacker-chosen value (0–31) into freed memory**,
plus a ~56-byte read of freed memory whose result steers a drop/forward decision (a weak but usable
oracle). The freed allocation is a `skb->head` — a `kmalloc` chunk of attacker-influenced size.
The free and the write happen on the same CPU inside one softirq, with no inter-CPU race, and the
sequence is repeatable per packet.

**Why it is not already fixed.** Nothing between `bpf_prog_run_save_cb()` and the
`seg6_bpf_has_valid_srh()` call refreshes `srh_state->srh`; `seg6_bpf_has_valid_srh()` re-reads the
cached field but never re-derives it from `skb->data` via `ipv6_find_hdr()` the way the seg6 helpers
do. There is no verifier restriction preventing `BPF_PROG_TYPE_LWT_SEG6LOCAL` from calling
`bpf_skb_pull_data` — `lwt_out_func_proto()` (`net/core/filter.c:8814`) in this tree returns the
proto unconditionally.

A secondary window exists in the same state: `bpf_lwt_seg6_adjust_srh()` returns early when
`bpf_skb_net_hdr_push()` fails, after the push may already have reallocated the head.

Still present in `2f1baf1fc8929e6c48370be543ad028ac7ad4131` (`v7.2-rc7-93-g2f1baf1fc892`).

## Trigger

Requires `CONFIG_IPV6_SEG6_LWTUNNEL=y`, which in turn selects `CONFIG_IPV6_SEG6_BPF=y`
(`def_bool y; depends on IPV6_SEG6_LWTUNNEL && IPV6=y`); without it neither `net/ipv6/seg6_local.c`'s
`End.BPF` action nor the `bpf_lwt_seg6_*` helpers are compiled in. Ubuntu, Fedora and Debian generic
kernels ship `CONFIG_IPV6_SEG6_LWTUNNEL=y`.

Privileges: `BPF_PROG_LOAD` of a `BPF_PROG_TYPE_LWT_SEG6LOCAL` program is gated by
`bpf_token_capable(NULL, CAP_BPF)` → `bpf_ns_capable(&init_user_ns, CAP_BPF)`
(`kernel/bpf/token.c:17`, `include/linux/capability.h:195`), i.e. real `CAP_BPF`, not user-namespace
escapable without a BPF token. The route half (`RTM_NEWROUTE` + `LWTUNNEL_ENCAP_SEG6_LOCAL`) only
needs `netlink_ns_capable(net->user_ns, CAP_NET_ADMIN)`, which *is* user-namespace reachable. Least
privilege on the whole path is therefore `CAP_BPF`.

1. Create a veth pair (or a dummy interface) in a network namespace and enable IPv6 segment routing
   on it.
2. Load a `BPF_PROG_TYPE_LWT_SEG6LOCAL` program that does, in order:
   a. `bpf_lwt_seg6_adjust_srh(skb, offset, len)` with an attacker-chosen `len` — this sets
      `srh_state->valid = false`, sets `srh_state->hdrlen += len` (the value that will later be
      written), and correctly re-derives `srh_state->srh`. `len` must keep `srh_state->hdrlen` a
      multiple of 8 for the write branch to be taken, and `offset` must point at the SRH TLV area
      (with a 2-segment SRH, `srh_tlvs == srh_end == skb->data + 80`);
   b. `bpf_skb_pull_data(skb, <len>)` — this reaches `pskb_expand_head()`, which frees the old
      `skb->head`. `srh_state->srh` now dangles;
   c. `return BPF_OK`.
3. Install the program as the action of an `End.BPF` seg6local route:
   `ip -6 route add <prefix> encap seg6local action End.BPF endpoint obj prog.o sec main dev <dev>`.
4. Arrange for `pskb_expand_head()` to actually free the head. Note that merely *cloning* the skb is
   not enough: with a clone alive, `pskb_expand_head()` takes the `skb_cloned(skb)` branch and calls
   `skb_release_data()`, which only drops `dataref` 2→1 and leaves the old head owned by the clone,
   so nothing is freed. The **non-linear** path does free it: `packet_alloc_skb()` keeps only
   `dev->hard_header_len` bytes linear once the frame is `>= PAGE_SIZE`, putting the rest in frags,
   with a `kmalloc`ed head; a subsequent `bpf_skb_pull_data()` → `skb_ensure_writable()` →
   `pskb_may_pull()` → `__pskb_pull_tail()` finds `eat = skb->tail + delta - skb->end > 0` (not
   enough tailroom) and forces `pskb_expand_head()` on an **un-cloned** skb → `skb_free_head()`, so
   the old head is genuinely `kfree()`d.
5. Send an IPv6 packet carrying a Segment Routing Header (next header 43, type 4, `segments_left`
   set) to `<prefix>`, large enough to be non-linear. `ip6_rcv_finish` → `dst_input` =
   `lwtunnel_input` → `seg6_local_input` → `input_action_end_bpf()` runs the program; on return
   `srh_state->srh` points into freed memory and `seg6_bpf_has_valid_srh()` writes one
   attacker-chosen byte into it and reads ~56 more.

The attacker controls the value of the written byte (via `adjust_srh`'s `len`), the size of the
freed `skb->head` (via the frame length), and the rate at which the sequence repeats (one packet per
attempt).
