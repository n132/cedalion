# mwifiex / nxpwifi: use-after-free read in `mwifiex_uap_queue_bridged_pkt()`

|  |  |
|---|---|
| Bug class | Use-after-free (read) |
| Subsystem | `drivers/net/wireless/marvell/mwifiex` (identical fork: `drivers/net/wireless/nxp/nxpwifi`) |
| Location | `drivers/net/wireless/marvell/mwifiex/uap_txrx.c` (`mwifiex_uap_queue_bridged_pkt()`) |

## Root cause

Two header pointers are captured at function entry and point **into the
original `skb->head`**:

```c
/* drivers/net/wireless/marvell/mwifiex/uap_txrx.c:94 */
	uap_rx_pd = (struct uap_rxpd *)(skb->data);
	rx_pkt_hdr = (void *)uap_rx_pd + le16_to_cpu(uap_rx_pd->rx_pkt_offset);
```

Later, on the insufficient-headroom path, the skb is reallocated and the
original is freed:

```c
	if (skb_headroom(skb) < MWIFIEX_MIN_DATA_HEADER_LEN) {
		...
		new_skb = skb_realloc_headroom(skb, MWIFIEX_MIN_DATA_HEADER_LEN);
		if (unlikely(!new_skb)) { ...; return; }

		kfree_skb(skb);		/* <-- frees the ORIGINAL head */
		skb = new_skb;
		...
	}
```

`skb_realloc_headroom()` with a positive delta does `skb_clone()` followed by
`pskb_expand_head(skb2, ...)`. The expand gives `skb2` a **new** head and drops
one reference on the original head's `dataref`; the following `kfree_skb(skb)`
drops the last one, so the **original head is freed**. Neither `uap_rx_pd` nor
`rx_pkt_hdr` is recomputed against `new_skb`.

Both stale pointers are then dereferenced:

```c
	src_node = mwifiex_get_sta_entry(priv, rx_pkt_hdr->eth803_hdr.h_source);	/* stale */
	if (src_node) {
		src_node->stats.last_rx = jiffies;
		src_node->stats.rx_bytes += skb->len;
		src_node->stats.rx_packets++;
		src_node->stats.last_tx_rate = uap_rx_pd->rx_rate;	/* stale */
		src_node->stats.last_tx_htinfo = uap_rx_pd->ht_info;	/* stale */
	}

	if (is_unicast_ether_addr(rx_pkt_hdr->eth803_hdr.h_dest)) {		/* stale */
```

The freed 6-byte MAC address at `rx_pkt_hdr->eth803_hdr.h_source` is used as the
**lookup key** for `mwifiex_get_sta_entry()`, so after a slab reuse the driver
attributes traffic statistics to a station chosen by whatever now occupies the
freed memory. `rx_pkt_hdr->eth803_hdr.h_dest` likewise decides the
unicast-vs-broadcast forwarding branch. Two freed bytes (`rx_rate`, `ht_info`)
are read from `uap_rx_pd` and written into the matched station's stats, so an
attacker who grooms the freed slab object gains an indirect, reuse-dependent
write into a `mwifiex_sta_node` chosen by the stale key.

The defect is present verbatim at commit `238650ef6c7c` in both copies.
`nxpwifi` is a recent fork (`73b01e57ed3e`) that reproduced the defect unchanged.

## Trigger

1. The victim runs a Marvell `mwifiex` (or NXP `nxpwifi`) adapter in **uAP
   (SoftAP) mode** with client-to-client bridging active.
2. An associated station transmits a frame destined for another station on the
   same BSS, so the uAP RX path calls `mwifiex_uap_queue_bridged_pkt()` to
   bridge it.
3. The frame is shaped so that, after `skb_pull(skb, hdr_chop)`, the remaining
   headroom is below `MWIFIEX_MIN_DATA_HEADER_LEN` — driven by the
   `rx_pkt_offset` the firmware reports in the `uap_rxpd`.
4. `skb_realloc_headroom()` + `kfree_skb()` free the original head; the
   following `rx_pkt_hdr->eth803_hdr.h_source` / `uap_rx_pd->rx_rate` reads hit
   freed slab memory.

The short-headroom branch is reliably reachable, not a narrow corner:
`MWIFIEX_MIN_DATA_HEADER_LEN = MWIFIEX_DMA_ALIGN_SZ(64) + INTF_HDR_ALIGN(4) +
MAX_TXPD_SZ(32) = 100`, while the RX skb is
`dev_alloc_skb(MWIFIEX_RX_DATA_BUF_SIZE)` whose headroom is `NET_SKB_PAD == 64`,
preserved verbatim by the `skb_copy()` on the multicast forward path.
`skb_pull(skb, hdr_chop)` raises the headroom to `64 + hdr_chop`, so the realloc
branch is taken for any `hdr_chop < 36`, and with `rx_pkt_offset == 0` (which the
driver's own bounds checks permit) `hdr_chop` is exactly 0, so the branch is
taken every time.

**Privilege required**: none beyond being an associated Wi-Fi client of the
victim AP. The same line is also reachable from an attacker-supplied USB
peripheral (VID `0x1286` / PID `0x204e`) bound by `mwifiex_usb`, whose crafted
RX data frame on the bulk data endpoint reaches
`mwifiex_uap_queue_bridged_pkt()` with no local account and no capabilities.

**Configuration exposed**: `CONFIG_MWIFIEX` built with a bus backend that can
bind the adapter (e.g. `CONFIG_MWIFIEX_USB` for the USB path). `CONFIG_KASAN`
makes the read fault observable but is not required to trigger it.
