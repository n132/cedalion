# ipv6: NULL pointer dereference in `rpfilter_lookup_reverse6()`

|  |  |
|---|---|
| Bug class | NULL pointer dereference |
| Subsystem | net/ipv6, net/ipv6/netfilter |
| Location | `net/ipv6/netfilter/ip6t_rpfilter.c:75` (`rpfilter_lookup_reverse6()`), produced at `net/ipv6/route.c:1183` (`ip6_rt_copy_init()`) |

## Root cause

`in6_dev_get()` (`include/net/addrconf.h:402`) is a genuine fallible try-get:

```c
static inline struct inet6_dev *in6_dev_get(const struct net_device *dev)
{
	struct inet6_dev *idev;

	rcu_read_lock();
	idev = rcu_dereference(dev->ip6_ptr);
	if (idev && !refcount_inc_not_zero(&idev->refcnt))
		idev = NULL;			/* device's idev is dying */
	rcu_read_unlock();
	return idev;
}
```

`ip6_rt_copy_init()` consumes it with a ternary that tests **the wrong thing**:

```c
/* net/ipv6/route.c:1175 — the producer; the ternary tests `dev`, not the acquisition */
static void ip6_rt_copy_init(struct rt6_info *rt, const struct fib6_result *res)
{
	const struct fib6_nh *nh = res->nh;
	const struct net_device *dev = nh->fib_nh_dev;
	struct fib6_info *f6i = res->f6i;

	ip6_rt_init_dst(rt, res);

	rt->rt6i_dst = f6i->fib6_dst;
	rt->rt6i_idev = dev ? in6_dev_get(dev) : NULL;
	rt->rt6i_flags = res->fib6_flags;
	...
}
```

The condition asks "is there a device?" — not "did the acquisition succeed?".
Both facts are in scope; only the irrelevant one is consulted.
`ip6_rt_copy_init()` is the shared initialiser for every dynamically built IPv6
route: `ip6_rt_cache_alloc()` (route.c:1391), `ip6_rt_pcpu_alloc()`
(route.c:1429) and `ip6_create_rt_rcu()` (route.c:1247).

`rt6i_idev == NULL` is a state the kernel itself acknowledges — four in-tree
consumers NULL-test it explicitly, which is what makes the unguarded ones stand
out:

| site | guard |
|---|---|
| `net/ipv6/icmp.c:434` | `if (rt6 && rt6->rt6i_idev) dev = rt6->rt6i_idev->dev;` |
| `net/ipv6/fib6_rules.c:243-245` | `idev = ip6_dst_idev(&rt->dst); if (!idev) goto again;` |
| `net/ipv6/xfrm6_policy.c:66-70`, `:133` | `if (!idev) { dst_release(dst); return -EHOSTUNREACH; }` |
| `net/ipv6/route.c:379` | `if (idev && idev->dev != blackhole_netdev)` |

`ip6_dst_idev()` (`include/net/ip6_fib.h:240`) is a bare field read — `return
dst_rt6_info(dst)->rt6i_idev;` — so it launders nothing.

The unguarded consumer is `rpfilter_lookup_reverse6()`,
`net/ipv6/netfilter/ip6t_rpfilter.c:75`:

```c
	rt = (void *)ip6_route_lookup(net, &fl6, skb, lookup_flags);
	if (rt->dst.error)                                  goto out;
	if (rt->rt6i_flags & (RTF_REJECT|RTF_ANYCAST))      goto out;
	if (rt->rt6i_flags & RTF_LOCAL) { ...               goto out; }

	if (rt->rt6i_idev->dev == dev ||                    /* <-- unguarded */
	    l3mdev_master_ifindex_rcu(rt->rt6i_idev->dev) == dev->ifindex ||
	    (flags & XT_RPFILTER_LOOSE))
```

Three guards, none about `rt6i_idev`. A route freshly built by
`ip6_route_lookup()` → `ip6_pol_route_lookup()` → `ip6_create_rt_rcu()` →
`ip6_rt_copy_init()` with a failed try-get has `dst.error == 0` and
`rt6i_idev == NULL`, sailing past all three. Note `XT_RPFILTER_LOOSE` is the
**third** disjunct, so it cannot short-circuit the deref. Contrast
`fib6_rules.c:243-245`, which NULL-checks the result of the *same*
`pol_lookup_func`.

A second consumer, `ip6_rcv_core()` at `net/ipv6/ip6_input.c:230`, has the same
shape:

```c
	IP6CB(skb)->iif = skb_valid_dst(skb) ?
				ip6_dst_idev(skb_dst(skb))->dev->ifindex :
				dev->ifindex;
```

The guard is `skb_valid_dst()` — "is a non-metadata dst attached?" — a
completely different predicate from "did the try-get that populated
`rt6i_idev` succeed?". This consumer is **not** reachable as described: every
in-tree way to get an skb into `ip6_rcv()` with a dst attached goes through
`ip6_output()`, which since `net/ipv6/ip6_output.c:239` drops the packet when
`ip6_dst_idev(dst)` is NULL. The exception is VRF (`vrf_ip6_input_dst()`).

**Consequence.** DoS only — a read at a small fixed offset off NULL
(`offsetof(struct inet6_dev, dev)`), unmappable under any default
`mmap_min_addr`. Kernel oops in
softirq/NAPI context — with `panic_on_oops` the whole box goes down.
Non-exploitable as memory corruption; a local, namespaced DoS.

Independently, `fib6_ifdown()`'s `if (... || rt->nh) return 0;` leaving
nexthop-object routes pointing at a device whose `ip6_ptr` was just cleared
looks like a second, arguably more fundamental defect.

## Trigger

An unprivileged user (uid != 0, no capabilities in `init_user_ns`) reaches the
oops through `unshare(CLONE_NEWUSER|CLONE_NEWNET)`: the whole setup then runs
under `ns_capable(net->user_ns, CAP_NET_ADMIN)` — `netlink_net_capable()` for
`RTM_NEWLINK`/`RTM_NEWNEXTHOP`/`RTM_NEWROUTE`, and
`ns_capable(net->user_ns, CAP_NET_ADMIN)` in `do_ip6t_set_ctl()` for
`setsockopt(IP6T_SO_SET_REPLACE)`.

No race is required. The sequence is straight-line:

1. Create two veth pairs — one to carry the route's nexthop, one for packet
   injection — and bring them up.
2. `RTM_NEWNEXTHOP`: an external nexthop object with `NHA_OIF` set to the
   nexthop device.
3. `RTM_NEWROUTE`: a prefix (e.g. `2001:db8:1::/64`) with `RTA_NH_ID` pointing
   at that object, so the resulting `fib6_info` has `rt->nh != NULL`.
4. `RTM_NEWLINK` with `IFLA_MTU = 1000` on the nexthop device. Because
   `1000 < IPV6_MIN_MTU`, `addrconf_notify()` (`net/ipv6/addrconf.c:3691`)
   calls `addrconf_ifdown(dev, true)`, which does
   `rt6_disable_ip(dev, NETDEV_UNREGISTER)` and then
   `RCU_INIT_POINTER(dev->ip6_ptr, NULL)` (`addrconf.c:3902`).
5. **The route survives step 4**: `fib6_ifdown()` (`net/ipv6/route.c:4977`)
   returns 0 immediately for any `fib6_info` with `rt->nh` set, and
   `nh_netdev_event()` (`net/ipv4/nexthop.c:3988`) only calls
   `nexthop_sync_mtu()` for `NETDEV_CHANGEMTU`, never `nexthop_flush_dev()`.
   No `NETDEV_UNREGISTER` is broadcast — the device is still registered and UP,
   and the route through it is still installed, with `ip6_ptr == NULL`.
6. Install `ip6tables -t raw -A PREROUTING -m rpfilter --loose -j ACCEPT` via
   `setsockopt(IP6T_SO_SET_REPLACE)`.
7. Inject an IPv6 frame on the second pair with `saddr` inside the route (e.g.
   `2001:db8:1::1234`) and `daddr = ff02::1` — multicast, so `rpfilter` leaves
   `fl6.saddr` unset and `lookup_flags = 0`, which makes `rt6_device_match()`
   take its `!oif && ipv6_addr_any(saddr)` fast path straight onto the
   nexthop's `fib6_nh`. It arrives on the peer, hits raw/PREROUTING, and
   `rpfilter_lookup_reverse6()` runs `ip6_route_lookup()` →
   `ip6_pol_route_lookup()` → `ip6_create_rt_rcu()` → `ip6_rt_copy_init()`.
8. `ip6_rt_copy_init()` (`net/ipv6/route.c:1183`) executes
   `rt->rt6i_idev = dev ? in6_dev_get(dev) : NULL;`. `dev` is non-NULL so the
   ternary takes the "success" branch, but `in6_dev_get()` returns NULL because
   the device's `ip6_ptr` is NULL. The `rt6_info` is published with
   `rt6i_idev == NULL` **and `dst.error == 0`**.
9. Back in `rpfilter_lookup_reverse6()` the three guards (`dst.error`,
   `RTF_REJECT|RTF_ANYCAST`, `RTF_LOCAL`) all pass, and line 75
   `rt->rt6i_idev->dev == dev` dereferences NULL in softirq/NAPI context.

The very first injected packet oopses.

**Required config.** The consumer needs `CONFIG_IP6_NF_IPTABLES`,
`CONFIG_IP6_NF_IPTABLES_LEGACY`, `CONFIG_IP6_NF_RAW` and
`CONFIG_IP6_NF_MATCH_RPFILTER`. `ip6tables -t raw -A PREROUTING -m rpfilter` is
a standard anti-spoofing rule and `CONFIG_IP6_NF_MATCH_RPFILTER=m` ships in
major distro configs. The producer defect in `net/ipv6/route.c:1183` is
config-independent.

Reaching it unprivileged additionally requires unprivileged user namespaces to
be permitted (`kernel.unprivileged_userns_clone=1`).
