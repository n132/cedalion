# usbip: NULL dereference and use-after-free in stub_recv_cmd_submit() error paths

|  |  |
|---|---|
| Bug class | NULL pointer dereference / slab use-after-free + double free |
| Subsystem | `drivers/usb/usbip` |
| Location | `drivers/usb/usbip/stub_rx.c:536-540`, `:641-645` (`stub_recv_cmd_submit()`) |

## Root cause

`stub_recv_cmd_submit()` error paths leave `priv->urbs` NULL or freed while
`priv->num_urbs` is already set, causing a NULL deref or use-after-free in the event
thread.

`stub_priv_alloc()` links `priv` onto `sdev->priv_init` immediately, and says so:

```c
	/*
	 * After a stub_priv is linked to a list_head,
	 * our error handler can free allocated data.
	 */
	list_add_tail(&priv->list, &sdev->priv_init);
```

so from that point the event thread owns cleanup. `stub_recv_cmd_submit()` then sets the
count **before** allocating the array it describes:

```c
	/* allocate urb array */
	priv->num_urbs = num_urbs;                      /* >= 1 */
	priv->urbs = kmalloc_objs(*priv->urbs, num_urbs);
	if (!priv->urbs)
		goto err_urbs;
```

and its error labels are:

```c
err_urb:
	kfree(priv->urbs);          /* freed, but priv->urbs NOT set to NULL */
err_urbs:
	kfree(buffer);
	sgl_free(sgl);
err_malloc:
	usbip_event_add(ud, SDEV_EVENT_ERROR_MALLOC);
}
```

Both labels end by raising `SDEV_EVENT_ERROR_MALLOC`, which wakes the event thread:
`stub_shutdown_connection()` → `stub_device_cleanup_urbs()`:

```c
	while ((priv = stub_priv_pop(sdev))) {
		for (i = 0; i < priv->num_urbs; i++)
			usb_kill_urb(priv->urbs[i]);

		stub_free_priv_and_urb(priv);
	}
```

Two distinct failures result:

1. **`err_urbs` → NULL dereference.** `priv->urbs` is NULL while `priv->num_urbs >= 1`, so
   `priv->urbs[0]` reads address 0. `stub_free_priv_and_urb()`'s `if (!urb) return;` guard
   is no help — the loop in `stub_device_cleanup_urbs()` dereferences the array first.

2. **`err_urb` → use-after-free.** `kfree(priv->urbs)` runs but the pointer is left in
   place, so the cleanup loop reads `priv->urbs[i]` out of freed slab memory and passes
   whatever it finds to `usb_kill_urb()`. `stub_free_priv_and_urb()` then dereferences the
   same freed array again (`kfree(urb->setup_packet)`, …) and finally `kfree(priv->urbs)`
   a second time — a double free on top of the UAF.

The in-tree comment inside the allocation loop states the contract that `err_urb`'s
`kfree(priv->urbs)` breaks:

```c
		for_each_sg(sgl, sg, nents, i) {
			priv->urbs[i] = usb_alloc_urb(0, GFP_KERNEL);
			/* The URBs which is previously allocated will be freed
			 * in stub_device_cleanup_urbs() if error occurs.
			 */
			if (!priv->urbs[i])
				goto err_urb;
```

— the previously allocated URBs are indeed meant to be freed by
`stub_device_cleanup_urbs()`, but `err_urb` destroys the array holding the only pointers to
them before that can happen (so those URBs leak as well).

## Trigger

usbip's stub (server) side is exposed to a remote client over TCP once a device is bound
and exported with `usbip bind` / `usbipd`.

1. Export a USB device on the victim host (`usbip bind -b <busid>`; `usbipd` listening).
2. A remote client attaches and issues `USBIP_CMD_SUBMIT` PDUs.
3. Drive the host into memory pressure so a small `GFP_KERNEL` allocation fails. A client
   can contribute to this directly by submitting many large `transfer_buffer_length`
   requests, each of which makes the server run `sgl_alloc()` for the requested size before
   reaching the array allocation.
4. When `kmalloc_objs(*priv->urbs, num_urbs)` fails, `err_urbs` is taken:
   `priv->num_urbs >= 1`, `priv->urbs == NULL`, and `SDEV_EVENT_ERROR_MALLOC` is raised.
5. The event thread runs `stub_shutdown_connection()` → `stub_device_cleanup_urbs()` →
   `usb_kill_urb(priv->urbs[0])` → **NULL dereference oops**.
6. Alternatively, when `usb_alloc_urb()` fails inside the `for_each_sg` loop, `err_urb` is
   taken and the same cleanup path performs a **use-after-free read** of the just-freed
   `priv->urbs` array, calls `usb_kill_urb()` on the garbage pointers it finds there, and
   double-frees the array. If the freed array is reallocated with client-influenced data
   before the event thread runs, the pointers handed to `usb_kill_urb()` are attacker-
   influenced.

**Reachability**: the usbip stub side, reachable by any client that can connect to
`usbipd` and attach an exported device — a network-facing surface. Both paths are gated
on a `GFP_KERNEL` allocation failure, so they are not deterministic; a client can raise
the probability by submitting many large-`transfer_buffer_length` requests, but cannot
force the failure directly. `np` is bounded by `USBIP_MAX_ISO_PACKETS` (validated at 379)
and `num_urbs = nents` requires `sgl_alloc()` to have already succeeded, so the array
size itself cannot be inflated to force the failure.

**Primitive**: `err_urbs` gives a NULL pointer dereference (kernel oops, DoS). `err_urb`
gives a slab use-after-free read of the URB pointer array, `usb_kill_urb()` invoked on
whatever pointers occupy the freed memory, and a double free of that array — a genuine
memory-corruption primitive if the freed allocation is reclaimed with controlled data
before the event thread drains it.

**Privilege required**: none locally. Remote: the ability to reach `usbipd` and attach
an exported device. Root on the *server* is required to export the device in the first
place, so the exposure exists only on hosts deliberately running a usbip server.

**Config**: `CONFIG_USBIP_HOST` — it is the driver that contains the bug. Any distro or
host that actually runs a usbip server (`usbip bind` / `usbipd`) has it (it is
`usbip-host.ko` in Debian/Ubuntu/Fedora `linux-modules-extra`).
